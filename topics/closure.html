一、基础概念

必练

Q1 · 什么是闭包？用一句话向面试官解释

用一句话说清什么是闭包。

查看答案

闭包 = 函数 + 其词法作用域（创建时能访问到的外部变量）的组合； 函数在定义作用域之外被调用时，仍能访问定义时的外部变量。

面试口述模板：

「当一个内部函数引用了外部函数的变量，且内部函数在外部函数执行完后 仍被引用时，就形成了闭包。JS 靠闭包实现私有变量、防抖节流等。」

选练

Q2 · 下面哪些会形成闭包？

📌 场景
// A
function outer() {
  const x = 1;
  function inner() {
    console.log(x);
  }
  return inner;
}

// B
function foo() {
  let count = 0;
  return () => ++count;
}

// C
function bar() {
  console.log("no outer var");
}

// D
const handlers = [];
for (let i = 0; i < 3; i++) {
  handlers.push(() => console.log(i));
}
查看答案
  • A ✅ inner 引用了 outer 的 x，且被 return 出去
  • B ✅ 箭头函数引用了 count，且被 return
  • C ❌ 没有引用外部变量
  • D ✅ 每个箭头函数形成闭包，各自捕获当次循环的 i（let 块级作用域）

二、经典坑题

必练

Q3 · var + 循环 + setTimeout

📌 场景
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("3-var", i), 0);
}

下面输出什么？如何改成输出 0 1 2？

查看答案

输出：3 3 3

原因：

  • var 没有块级作用域，循环结束后 i === 3
  • 三个 setTimeout 共享同一个 i，执行时已是 3

改成 0 1 2 的三种方式：

  1. 用 let（推荐）—— 每次循环新绑定
  2. IIFE：setTimeout((function(j){ return () => console.log(j); })(i), 0)
  3. setTimeout 第三参：setTimeout((j) => () => console.log(j), 0, i)
选练

Q4 · let + 循环 + setTimeout

📌 场景
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log("4-let", i), 0);
}

下面输出什么？和 Q3 有何不同？

查看答案

输出：0 1 2

原因：

let 在 for 循环里每次迭代创建新的词法环境，每个闭包捕获各自的 i。

Q5 · 防抖 debounce

📌 场景

搜索框输入时调接口，用户每敲一个字都会发请求，浪费且卡顿。 需求：停止输入 300ms 后再发请求。

为什么闭包适合做这个？手写 debounce(fn, delay)。

查看答案

为什么用闭包：

需要跨多次调用「记住」timerId，且不能污染全局 —— 闭包私有变量最合适。 

function debounce(fn, delay) {
  let timer = null;
  return (...args) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

场景：搜索联想、表单校验、窗口 resize 结束后重新布局。

Q6 · 节流 throttle

📌 场景

滚动监听、resize、按钮防重复点击——高频事件里限制执行频率。 需求：无论触发多频繁，最多每 200ms 执行一次。

节流和防抖的区别？各自适合什么场景？

查看答案

区别：

  • 防抖：连续触发只认「最后一次」，适合搜索输入
  • 节流：固定间隔最多执行一次，适合 scroll / mousemove / 按钮连点
function throttle(fn, interval) {
  let last = 0;
  let timer = null;
  return (...args) => {
    const now = Date.now();
    const remaining = interval - (now - last);
    if (remaining <= 0) {
      if (timer) { clearTimeout(timer); timer = null; }
      last = now;
      fn(...args);
    } else if (!timer) {
      timer = setTimeout(() => {
        last = Date.now();
        timer = null;
        fn(...args);
      }, remaining);
    }
  };
}

Q7 · 私有变量 / 模块模式

📌 场景

做一个计数器，外部只能 +1 和读值，不能直接改内部 count。

不用 class private，如何用闭包实现 createCounter()？

查看答案 
function createCounter() {
  let count = 0; // 闭包私有，外部无法直接访问
  return {
    increment: () => ++count,
    getCount: () => count,
  };
}

场景：

  • 模块模式（ES Module 之前常用）
  • 不想暴露内部状态的工厂函数
  • 替代 class private 的轻量方案

Q8 · 只执行一次 once

📌 场景

初始化配置、埋点上报「页面只报一次」、懒加载单例。

用闭包实现 once(fn)，第二次起返回第一次的结果。

查看答案 
function once(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

场景：初始化只跑一次、单例 getInstance、首次访问埋点。

Q9 · 柯里化 curry

📌 场景
const add = (a, b, c) => a + b + c;
const curriedAdd = curry(add);
curriedAdd(1)(2)(3) === 6
curriedAdd(1, 2)(3) === 6

柯里化在实际项目里有什么用？（提示：参数复用、偏函数）

查看答案

实际用途：

  • 固定部分参数：const logError = curry(log)('ERROR')
  • 配置复用：createRequest(baseURL)(path)(options)
  • 函数组合 pipeline
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return (...next) => curried.apply(this, args.concat(next));
  };
}

Q10 · 缓存 memoize

📌 场景

斐波那契、复杂计算、接口结果缓存——相同入参不重复计算。

闭包里的 cache 对象为什么不会被 GC 掉？

查看答案 
function memoize(fn) {
  const cache = new Map();
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

为什么 cache 不被 GC：

返回的函数仍被引用 → 闭包链活着 → cache 一直被持有。 这是刻意的设计（用空间换时间），但若 cache 无限增长需设上限或 WeakMap。

Q11 · 独立闭包输出

📌 场景
function make() {
  let a = 0;
  return {
    get: () => a,
    set: (v) => { a = v; },
  };
}
const c1 = make();
const c2 = make();
c1.set(10);
console.log("11", c1.get(), c2.get());

下面输出什么？

查看答案

输出：11 10 0

c1、c2 各自独立闭包，互不影响。

Q12 · 闭包会导致内存泄漏吗？

闭包会导致内存泄漏吗？什么情况下会？如何避免？

查看答案

闭包本身不是泄漏，但：

  • 闭包长期持有大对象引用（DOM 节点、大数组）
  • 忘记 removeEventListener
  • 定时器未 clear

避免：

  • 只闭包需要的变量（Q13 里应只闭包 id，不引 hugeData）
  • 组件卸载时清理 listener / timer
  • 需要时用 WeakMap 做缓存
选练

Q13 · 内存陷阱

📌 场景
const hugeData = new Array(1_000_000).fill("x");

function createHandler() {
  const id = 1;
  return () => console.log(id, hugeData.length);
}

const handler = createHandler();
// handler 还在，hugeData 就释放不了

下面有什么问题？如何修复？

查看答案

createHandler 闭包引用了整个 hugeData，但只用 id。 handler 存活期间 hugeData 无法释放 → 浪费内存。

修复：

function createHandler() {
  const id = 1;
  return () => console.log(id); // 不引用 hugeData
}

React 里 useEffect / useState 和闭包有什么关系？ 为什么有时 setState 里读到的是「旧值」？

查看答案

Q15 · 事件监听器闭包

📌 场景
let count = 0;
const btn = { addEventListener: (_, fn) => fn }; // 模拟

for (var i = 0; i < 3; i++) {
  btn.addEventListener("click", () => {
    count++;
    console.log("15", i, count);
  });
}
// 模拟点 3 次

事件监听器里用闭包要注意什么？点击 3 次后，期望输出什么？

查看答案

for (var i...) 注册了 3 个 listener，都共享 i === 3。 点一次按钮三个 listener 都触发，各打 15 3 1 / 15 3 2 / 15 3 3（count 递增）。

实际 DOM 里通常只绑一个 listener 或用事件委托更好。
