一、渲染流水线

必练

Q1 · 浏览器从 HTML 到屏幕像素经历了什么？

📌 场景

用户打开你的 SPA，Network 里 JS/CSS 都 200 了，但白屏很久才出内容—— 面试官问「从下载完 HTML 到用户看见画面，浏览器做了什么？」

查看答案

简化流水线（常背版）：

  1. 解析 HTML → 构建 DOM 树
  2. 解析 CSS → 构建 CSSOM
  3. DOM + CSSOM → 渲染树（Render Tree，不含不可见节点）
  4. Layout（布局 / 重排） → 计算几何位置尺寸
  5. Paint（绘制 / 重绘） → 填充像素（颜色、边框、阴影等）
  6. Composite（合成） → 图层合成上屏

面试口述：「解析建树 → 布局 → 绘制 → 合成；JS 可能阻塞解析，CSS 阻塞渲染。」

资源加载与缓存策略见 浏览器缓存。

必练

Q2 · 重排、重绘、合成有什么区别？成本谁高？

📌 场景

性能面板里看到 Recalculate Style、Layout、Paint、Composite Layers—— 改 width、改 color、改 transform 分别会触发哪些？

查看答案
名称别名做什么成本
重排 Reflow / Layout 重新计算元素几何（位置、大小） 高（可能牵连整页）
重绘 Repaint / Paint 外观变化但不影响布局（颜色等） 中
合成 Composite GPU 合成已有图层 低（理想动画路径）

记忆：布局变 → 重排；只变外观 → 可能只重绘；transform / opacity 常走合成，不触发布局。

二、什么触发重排 & 怎么避免

必练

Q3 · 哪些常见操作会触发重排？

📌 场景

下面哪些在滚动监听里做会卡？

  • A. el.style.width = el.offsetWidth + 1 + 'px'
  • B. el.style.color = 'red'
  • C. el.style.transform = 'translateX(10px)'
  • D. document.body.appendChild(newNode)
  • E. window.getComputedStyle(el).height 后立刻改 width
查看答案

会触发 / 可能触发重排：A、D、E（读布局 + 写布局）

通常不触发布局：B（重绘）、C（合成，见 Q4）

常见重排触发：

  • 改 width/height/margin/padding/display/position 等几何相关属性
  • 增删 DOM、改变字体、窗口 resize
  • 读取 offsetWidth、getBoundingClientRect 等（强制同步布局）
必练

Q4 · 动画用 left/top 还是 transform？

📌 场景

要做一个 60fps 的侧边栏滑入动画，同事写了 setInterval 不断改 left，Chrome Performance 里 Layout 条爆红——怎么改？

查看答案

推荐：transform: translateX() + transition 或 CSS @keyframes，配合 will-change: transform（慎用、动画结束去掉）。

.sidebar {
  transform: translateX(-100%);
  transition: transform 0.3s ease;
}
.sidebar.open {
  transform: translateX(0);
}

原因：

  • left/top 改变布局 → 每帧重排，主线程压力大
  • transform / opacity 可提升为合成层，GPU 参与，不触发布局

动画时机可配合 requestAnimationFrame，在下一帧绘制前更新。

选练

Q5 · 合成层 / will-change 是什么？滥用有何问题？

📌 场景

听说给元素加 transform: translateZ(0) 或 will-change: transform 能「硬件加速」，于是给全站 div 都加了——会有什么问题？

查看答案

合成层：某些元素单独成层，由 GPU 合成，适合独立动画。

常见提升手段：will-change、3D transform、opacity 动画、<video> / canvas 等。

滥用问题：

  • 层太多 → 内存暴涨（移动端尤其明显）
  • 层爆炸 → 合成阶段反而更慢
  • will-change 应短期使用，动画完移除

面试答法：「合成能避开重排，但层不是越多越好，按动画元素精准提升。」

必练

Q6 · 布局抖动（layout thrashing）怎么产生？怎么修？

📌 场景
// 根据每个 li 的高度动态设置容器高度
items.forEach((el) => {
  const h = el.offsetHeight; // 读布局
  el.style.marginBottom = '10px'; // 写样式 → 强制同步布局
});
container.style.height = total + 'px';

循环里交替「读布局 + 写样式」，页面突然很卡——这叫什么？怎么批量处理？

查看答案

布局抖动：在一帧内多次「读布局属性 → 写样式」，浏览器被迫反复强制同步布局（Forced Synchronous Layout）。

修复：读写分离

// ✅ 先批量读
const heights = items.map((el) => el.offsetHeight);
// 再批量写
items.forEach((el, i) => {
  el.style.marginBottom = '10px';
});
container.style.height = heights.reduce((a, b) => a + b, 0) + 'px';

其它手段：用 requestAnimationFrame 合并 DOM 写操作；文档片段 DocumentFragment 批量插入；虚拟列表减少 DOM 数量。

三、性能指标 & 首屏优化

选练

Q7 · FP / FCP / LCP / CLS 分别是什么？

📌 场景

老板要看 Core Web Vitals，报表里有 LCP 2.8s、CLS 0.15—— 各指标在衡量什么？优化时优先盯哪个？

查看答案
指标含义体验
FPFirst Paint 首次绘制任意像素首次出现
FCPFirst Contentful Paint首屏有文字/图片等内容
LCPLargest Contentful Paint最大内容块渲染完成（Core Web Vital）
CLSCumulative Layout Shift累积布局偏移（Core Web Vital）
INPInteraction to Next Paint交互响应（取代 FID）

优化优先级（常考）：LCP（首屏大图/字体/阻塞 JS）、CLS（图片无尺寸、动态插入横幅）、INP（长任务阻塞主线程）。

必练

Q8 · 首屏慢怎么排查和优化？

📌 场景

Vite 打包的 SPA：Lighthouse 显示 LCP 3.5s，主要耗时在「加载 JS」和「渲染阻塞」—— 你会从哪几条线优化？（结合缓存策略）

查看答案

排查：Network（瀑布图）、Performance、Lighthouse、Coverage（无用 JS/CSS）。

优化清单（面试背 5 条即可）：

  1. 资源体积：代码分割、Tree Shaking、压缩、图片 WebP/懒加载
  2. 加载策略：路由懒加载、defer/async、非关键 JS 延后
  3. 缓存：hash 静态资源长缓存 + index.html 短缓存（见 缓存 Q5）
  4. 渲染阻塞：关键 CSS 内联或优先、字体 font-display: swap、减少首屏依赖链
  5. 传输：CDN、HTTP/2 多路复用、Gzip/Brotli、预连接 preconnect

SSR/SSG：首屏直出 HTML，改善 FCP/LCP（框架向加分项）。

四、项目实战

选练

Q9 · 长列表卡顿怎么优化？

📌 场景

订单列表 5000 条全渲染进 DOM，滚动掉帧、内存高—— 除了「分页加载」，前端渲染层还能怎么做？

查看答案

核心思路：减少 DOM 数量 + 减少重排重绘

  • 虚拟列表（Virtual Scroll）：只渲染可视区 + 缓冲区（react-window、vue-virtual-scroller）
  • 分页 / 无限滚动：数据分批，DOM 有上限
  • DocumentFragment 批量插入，减少回流次数
  • 避免滚动中读 offsetHeight、避免复杂选择器

面试答法：「DOM 过多是根因，虚拟列表只保留视口内节点，配合 rAF 更新滚动位置。」

选练

Q10 · script defer/async、CSS 放哪、preload 怎么用？

📌 场景

index.html 里同时有统计 SDK、业务 bundle、首屏关键 CSS—— 标签怎么放才不阻塞首屏？和渲染阻塞什么关系？

查看答案
方式行为
默认 <script> 下载并执行，阻塞 HTML 解析
async 异步下载，下完立即执行，不保证顺序
defer 异步下载，DOM 解析完后按顺序执行
CSS <link> 默认阻塞渲染（构建 CSSOM）

实践：

  • 业务主 bundle → defer（或模块 type="module" 默认 defer）
  • 独立统计 → async
  • 关键字体/首图 → <link rel="preload">
  • 非关键 CSS 可异步加载（注意 FOUC 权衡）
必练

Q11 · 图片懒加载怎么实现？和首屏 LCP 什么关系？

📌 场景

选片页 3000 张缩略图，首屏只显示 20 张——如何延迟加载其余？

查看答案
  • 原生：<img loading="lazy">（简单场景）
  • Intersection Observer：进入视口再设 src（data-src 占位）
  • 响应式：srcset + 合适尺寸，避免大图
  • webp/AVIF 降级

LCP：最大内容元素常为 hero 图；首屏关键图 preload + 不用 lazy；非首屏才懒加载。

Vue 列表优化见 Vue3 Q11。

Q12 · 小程序 setData 和 Web 渲染优化有何不同？

📌 场景

同一长列表，Web 用虚拟滚动，小程序还要额外注意什么？

查看答案

小程序额外成本：逻辑层 ↔ 渲染层通信，setData 序列化开销。

  • 控制单次 setData 数据量（< 256KB 经验值）
  • 路径更新 'list[3].name' 而非整表
  • recycle-view / 分页代替全量节点

详见 小程序 Q1/Q7。
