一、HTTP 基础

必练

Q1 · GET / POST / PUT / PATCH / DELETE 区别？什么是幂等？

📌 场景

选片项目：查询项目列表、创建订单、更新选片状态、删除回收站项目—— 各该用哪个方法？「支付回调重复通知」和幂等有什么关系？

查看答案
方法语义幂等典型场景
GET查询✅列表、详情
POST创建 / 非幂等操作❌下单、上传凭证
PUT整体替换✅全量更新资源
PATCH部分更新视实现改单个字段
DELETE删除✅删项目

幂等：同一请求执行多次，效果与执行一次相同。支付回调用业务幂等键（订单号）防重复扣款，与方法是否幂等配合设计。

注意：GET 不应带 body 改数据；敏感操作勿用 GET（会进日志/缓存）。

必练

Q2 · 常见状态码：401 / 403 / 404 / 502 各表示什么？

📌 场景

Axios 拦截器里要根据状态码做不同提示：Token 过期跳转登录、无权限弹窗、 网关挂了显示「服务繁忙」——分别对应哪些码？

查看答案
状态码含义前端处理
200成功正常解析 body
201创建成功常配合 POST
204成功无 bodyDELETE 常见
301/302重定向浏览器自动跳
304未修改协商缓存，见 缓存专题
400请求参数错误展示校验信息
401未认证Token 缺失/过期 → 登录
403已认证但无权限提示无权限，非登录问题
404资源不存在空态页
429限流稍后重试
502/503网关/服务不可用服务繁忙，可重试

401 vs 403：401「你是谁？」→ 登录；403「我知道你是谁，但你不能」→ 权限不足。

选练

Q3 · HTTP/1.1 和 HTTP/2 主要区别？

📌 场景

首屏要加载几十个 JS/CSS 小文件，HTTP/2 对前端性能有什么帮助？

查看答案
  • 多路复用：一个 TCP 连接并行传多个请求，缓解队头阻塞（应用层）
  • 头部压缩：HPACK 减小重复 Header 体积
  • 服务端推送：可主动推资源（实际用得少）
  • HTTP/3 基于 QUIC（UDP），进一步改善弱网

前端关联：仍建议合并过大资源、CDN、缓存；HTTP/2 不是不用打包拆分，但小文件过多惩罚变小。

二、HTTPS

选练

Q4 · HTTPS 握手大致做什么？为什么需要证书？

📌 场景

生产环境强制 HTTPS，开发环境 localhost 用 HTTP——HTTPS 比 HTTP 多了哪几层保障？

查看答案

三大目标：机密性（加密）、完整性（防篡改）、身份认证（证书验服务器）。

简化流程（TLS）：

  1. Client Hello（支持的加密套件）
  2. Server Hello + 证书（公钥）
  3. 客户端验证证书链（CA 签发）
  4. 协商对称密钥，后续用对称加密传数据

前端关注：混合内容（HTTPS 页加载 HTTP 资源）会被拦；Cookie Secure 仅 HTTPS 传输。

三、JWT & 鉴权

必练

Q5 · JWT 结构是什么？Access / Refresh 怎么配合？

📌 场景

BPO 平台接企业微信 OAuth2 登录，后端返回 JWT—— 前端 Axios 怎么带 Token？过期了怎么无感刷新？

查看答案

JWT 三段：Header.Payload.Signature（Base64URL，签名防篡改）

Payload 常见字段：sub（用户 id）、exp（过期）、自定义角色/权限。

双 Token 模式：

  • Access Token：短命（如 2h），放 Header Authorization: Bearer xxx
  • Refresh Token：长命，只用于换新 Access（放 HttpOnly Cookie 或安全存储）
// 拦截器伪代码
if (res.status === 401 && !retried) {
  await refreshToken();
  return axios(originalRequest);
}

OAuth2 流程（口述）：跳转授权页 → 用户同意 → 回调带 code → 后端换 token → 前端存 token 调 API。

必练

Q6 · Token 存 localStorage 还是 Cookie？

📌 场景

有人把 JWT 存 localStorage 方便 Axios 读取； 安全同事要求改 HttpOnly Cookie——两种方案分别防什么、怕什么？

查看答案
存储防 CSRF防 XSS 窃取
localStorage + Bearer Header 相对不怕（跨站默认不带） ❌ XSS 可读 localStorage
HttpOnly Cookie 需 SameSite + CSRF Token ✅ JS 读不到

结论：没有银弹——XSS 要靠输入过滤、CSP、框架转义；CSRF 靠 SameSite、CSRF Token、校验 Origin。

Electron 桌面端 token 存储另论：可用 safeStorage / 系统钥匙串，勿明文写本地文件。

四、XSS & CSRF

必练

Q7 · XSS 有哪几种？前端怎么防？

📌 场景

IM 聊天里用户发了 <img onerror="steal(token)">， 富文本评论有人贴 <script>——分别属于哪类 XSS？Vue 里要注意什么？

查看答案
类型注入点例子
存储型入库后展示给所有人评论区脚本持久化
反射型URL 参数立即回显?q=<script>
DOM 型前端错误拼进 DOMinnerHTML = userInput

防御：

  • 默认转义输出；Vue 模板自动转义文本插值
  • 避免 v-html 渲染不可信内容；必须用时先消毒（DOMPurify）
  • CSP 限制脚本来源
  • HttpOnly Cookie 降低 XSS 后盗 token 风险
必练

Q8 · CSRF 是什么？和跨域、Cookie 什么关系？

📌 场景

用户登录银行后访问恶意站，恶意页自动 POST 转账—— 为什么浏览器会带上银行 Cookie？和 CORS 拦得住吗？

查看答案

CSRF：利用浏览器自动带 Cookie，诱使用户在已登录状态下执行非本意请求。

与 CORS：CORS 防的是「恶意站读响应」；CSRF 的表单提交/图片请求可能不需要读响应，CORS 拦不住写操作本身。

防御：

  • SameSite Cookie（Lax/Strict）
  • CSRF Token（双重 Cookie / 自定义 Header）
  • 校验 Origin / Referer
  • 敏感操作用 POST + 二次验证

Cookie 跨域细节见 跨域 Q8。

Q9 · 前端请求层怎么统一设计？

📌 场景

Monorepo 里 Web、小程序、Electron 共用 shared-api—— 拦截器、错误码、重试、取消请求怎么沉淀？

查看答案
  • 请求拦截：注入 Token、TraceId、平台标识
  • 响应拦截：统一业务 code（非 HTTP 状态码）、401 刷新/登出、错误 toast
  • 错误分类：网络错误 / 超时 / 4xx 业务 / 5xx 服务
  • 重试：仅幂等 GET 或带幂等键的 POST（链 并发 Q7）
  • 取消：AbortController，路由切换取消在飞请求
  • 类型：TS 泛型包装 ApiResponse<T>，与后端字段约定一致

Q10 · WebSocket 和 HTTP 长轮询怎么选？

📌 场景

OpenIM 即时通信、订单状态推送——什么时候用 WebSocket，什么时候 HTTP 轮询就够？

查看答案
WebSocketHTTP 轮询 / SSE
连接全双工长连接短连接反复请求 / SSE 单向流
适用IM、协作、高频推送低频状态查询、简单通知
成本连接维护、心跳、重连实现简单，频繁轮询浪费

IM 实践：WebSocket + 心跳 + 断线重连 + 本地未读缓存；鉴权可在握手时带 token。
