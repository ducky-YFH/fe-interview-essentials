Q2 · Vue3 响应式原理：为什么用 Proxy？

📌 场景

选片项目状态里有嵌套对象 project.meta.client， 后期动态新增 project.extraTags = [] 也要触发视图更新—— Vue2 和 Vue3 在这里有何不同？

查看答案

Vue3：用 Proxy 代理整个对象，拦截 get/set/deleteProperty 等。

优势（相对 Vue2 defineProperty）：

  • 能监听新增 / 删除属性（Vue2 需 Vue.set）
  • 能监听数组下标 / length 等（Vue2 需 hack）
  • 一次代理整对象，不用递归 defineProperty 到每层（Vue3 仍是惰性深层代理）

简述流程：

  1. reactive(obj) → 返回 Proxy
  2. get 时 track 收集依赖（当前活跃的 effect）
  3. set 时 trigger 通知依赖更新 → 调度组件重新渲染

注意：Proxy 无法代理非对象（基本类型）→ 用 ref 包一层。

Q3 · ref 和 reactive 怎么选？有哪些坑？

📌 场景
const count = ref(0);
let state = reactive({ list: [] });

// 解构后 list 还会更新吗？
const { list } = state;

// 整体替换 state 会怎样？
state = reactive({ list: [1, 2] });
查看答案

选型：

  • ref：基本类型、或需要整体替换的单一值；模板里自动解包
  • reactive：结构固定的对象/集合，按属性读写

经典坑：

  • 解构丢失响应式：const { list } = state → 用 toRefs(state) 或 storeToRefs(piniaStore)
  • 整体赋值丢失：let state = reactive(...); state = {...} 不行 → 改属性或改用 ref
  • ref 在 script 里要 .value，模板里自动解包

项目建议：Pinia store 解构用 storeToRefs 保留响应式；actions 直接从 store 取。

Q4 · 虚拟 DOM 是什么？Vue3 Diff 大致怎么做？

📌 场景

底片墙一次渲染 200 张缩略图，改其中一张的选中态—— Vue 怎么知道更新哪一块 DOM，而不是整页重绘？

查看答案

虚拟 DOM：用 JS 对象描述真实 DOM 结构；数据变 → 生成新 VNode 树 → 与旧树 Diff → 得到最小 patch → 更新真实 DOM。

Vue3 Diff 要点（口述版）：

  • 同层比较，不跨层（降低复杂度）
  • 用 key 标识节点，列表 Diff 时双端指针 + 最长递增子序列优化移动
  • 编译期标记静态节点（PatchFlag、Block Tree）→ 跳过不变部分，只追踪动态节点

面试答法：「不是虚拟 DOM 一定快，而是把多次变更批量成最小 DOM 操作；Vue3 靠编译优化减少 Diff 范围。」

浏览器真实渲染见 渲染&性能。

Q5 · nextTick 解决什么问题？和 Event Loop 什么关系？

📌 场景
selectedIds.value.push(id);
// 立刻量高度 — 拿不到最新 DOM
const h = galleryRef.value.offsetHeight;

选片后列表变长，要滚动到新项，但 DOM 还没更新——怎么办？

查看答案

原因：Vue 把同一 tick 内的状态变更批量异步更新 DOM（微任务队列），同步代码里 DOM 仍是旧的。

解法：

selectedIds.value.push(id);
await nextTick();
galleryRef.value?.scrollIntoView({ ... });

和 Event Loop：nextTick 默认用 Promise 微任务，在 DOM patch 完成后执行回调。详见 事件循环 Q8。

Q6 · v-if 和 v-show？v-for 为什么要 key？

📌 场景

底片列表 5000 项：用 v-if 做 Tab 切换 vs v-show； 列表用 index 做 key 导致输入框内容错乱——为什么？

查看答案
v-ifv-show
DOM条件假 → 不渲染/销毁始终渲染，切 display
切换成本高（重建）低（只改 CSS）
适用不常切换、要懒加载频繁显隐（如筛选面板）

key：帮助 Diff 识别节点身份。用 index 作 key，插入/删除/排序时节点被复用 → 子组件状态错乱。列表用稳定唯一 id（如 photoId）。

Q7 · Pinia 和 Vuex 比有什么优势？怎么设计业务状态流？

📌 场景

选片项目有七阶段状态：待发送 → 待选片 → 已选片 → 待精修 → 待确认 → 已交片 → 已完成。 多端（Web / Electron / 小程序）共享 Pinia store，怎么组织？

查看答案

Pinia vs Vuex：

  • 无 mutations，actions 里可直接改 state（也可保持不可变风格）
  • 天然 TS 支持、模块化无需嵌套 modules
  • 体积更小，支持 Composition API 风格定义 store
  • DevTools 友好
export const useProjectStore = defineStore('project', () => {
  const stage = ref<ProjectStage>('pending_send');
  const photos = ref<Photo[]>([]);

  const canUpload = computed(() =>
    ['pending_send', 'pending_select'].includes(stage.value)
  );

  async function advanceStage(next: ProjectStage) {
    // 校验 + 调接口 + 更新本地
    stage.value = next;
  }

  return { stage, photos, canUpload, advanceStage };
});

设计建议：

  • 阶段枚举 + 状态机校验（非法流转拒绝）
  • 派生状态用 computed（如 canUpload）
  • 异步放 actions；多端共用 store 定义放 Monorepo 公共包

Q8 · computed、watch、watchEffect 怎么选？

📌 场景
  • A. 根据已选 id 列表算「已选张数 / 是否超限」
  • B. 路由 query 变化时重新拉项目详情
  • C. 上传进度变化时同步到任务中心 UI
查看答案
API用途上面场景
computed 有缓存的派生值，依赖不变不重算 A ✅
watch 监听特定源，可拿新旧值，适合异步副作用 B ✅（watch route.query.id）
watchEffect 自动收集依赖，立即执行，适合同步副作用 C 可用，注意清理

注意：watch 默认懒执行；深度监听大对象有性能成本；副作用里注意 onCleanup 取消请求（链 并发 Q9）。

Q9 · 组件通信方式有哪些？跨层怎么传？

📌 场景

工作台深层子组件要读「当前项目 id」和「上传任务进度」，中间隔了 Layout、Sidebar 多层—— 不想 props 钻透，有哪些方案？

查看答案
  • props / emit — 父子直接通信
  • provide / inject — 跨层依赖注入（适合主题、项目上下文）
  • Pinia — 全局/模块业务状态（推荐用于项目 id、任务中心）
  • 事件总线 — Vue3 已移除，用 mitt 或 Pinia
  • ref 暴露 — defineExpose + 父调子方法（少用）

项目建议：业务状态进 Pinia；纯 UI 上下文用 provide/inject；避免全局事件滥用。

Q10 · keep-alive 和 LRU 多标签页缓存怎么用？

📌 场景

BPO 平台多标签页并行编辑考勤表单，切走再回来希望保留填写状态， 但开太多标签内存撑不住——你怎么做缓存策略？

查看答案 
<router-view v-slot="{ Component }">
  <keep-alive :max="10" :include="cachedNames">
    <component :is="Component" :key="route.fullPath" />
  </keep-alive>
</router-view>

要点：

  • include/exclude 按组件 name 控制缓存
  • max 超出时 LRU 淘汰最久未访问实例
  • 配合路由 meta keepAlive: true 动态维护 cachedNames
  • 缓存组件用 onActivated / onDeactivated 刷新数据

Q11 · 大量图片列表在 Vue3 里怎么优化？

📌 场景

客户选片页一次加载 3000 张缩略图，滚动卡顿、内存涨—— 结合你在猫咔项目里的实践，从 Vue 和浏览器两侧怎么说？

查看答案

Vue 侧：

  • 虚拟列表 — 只渲染视口 + 缓冲区（vue-virtual-scroller 等）
  • 稳定 key（photoId），避免错误复用
  • 大图用 shallowRef 存列表，避免深层响应式开销
  • v-memo 缓存子树（Vue3.2+）
  • 路由/Tab 懒加载，非首屏组件 defineAsyncComponent

资源侧：

  • 缩略图而非原图；懒加载 loading="lazy"
  • 分批请求、Intersection Observer 进入视口再加载
  • Electron 用主进程 Sharp 生成缩略图，减轻渲染进程压力

浏览器渲染原理见 渲染 Q9。

Q12 · 如何把业务 Hooks 沉淀到 Monorepo 公共包？

📌 场景

Web、Electron、小程序都要用「分页列表 + 上传 + 登录鉴权」， 你在 pnpm workspace 里怎么拆 packages，避免三端各写一套？

查看答案

分层思路：

packages/
  shared-types/     # TS 类型、枚举（ProjectStage）
  shared-utils/     # 纯函数、MD5、路径处理
  shared-api/       # 请求封装、拦截器、错误码
  shared-composables/ # usePagination、useUpload（无 UI）
  ui-web/           # Ant Design Vue 组件
  app-electron/
  app-miniapp/      # UniApp 适配层

原则：

  • Composables 只依赖 Vue 响应式 + 纯逻辑，不绑具体 UI 库
  • 平台差异（文件选择、存储）用 adapter 接口，各端实现
  • 状态枚举、接口类型统一，减少联调返工

面试答法：「逻辑下沉 composables + types，UI 和平台能力各 app 适配，这是我在猫咔 Monorepo 的做法。」

Q13 · Vue3 生命周期有哪些？keep-alive 下 onActivated 何时触发？

📌 场景

多标签页缓存的表单页，从列表切回来要刷新数据但不丢滚动——用哪个钩子？

查看答案

Composition API：

  • onBeforeMount / onMounted — DOM 挂载
  • onBeforeUpdate / onUpdated — 响应式数据变触发重渲染
  • onBeforeUnmount / onUnmounted — 销毁清定时器、取消请求
  • onActivated / onDeactivated — keep-alive 缓存组件切回/切走

实践：首次拉数放 onMounted；缓存页每次显示刷新用 onActivated；副作用清理放 onUnmounted + watch onCleanup。

Vue2 对照见 Vue2 Q3。

slot：

  mounted: (el) => el.focus()
}
