一、两大缓存

必练

Q1 · 强缓存 vs 协商缓存

📌 场景

用户第二次打开淘宝首页，很多图片「秒开」——是没发请求，还是发了请求但返回 304？两种都可能，分别对应哪层缓存？

查看答案
强缓存 协商缓存
是否发请求 不发（200 from cache） 发请求，服务器决定 304 或 200
关键响应头 Cache-Control / Expires ETag / Last-Modified
场景体感 图片秒开、零网络 Network 里看到 304

完整流程：

  1. 先看强缓存是否未过期 → 直接用
  2. 过期 → 带 If-None-Match 请求服务器
  3. 未变 → 304 用本地副本；变了 → 200 + 新内容

二、Cache-Control

必练

Q2 · 各场景 Cache-Control 怎么配？

📌 场景
  • A. 打包后的 app.a1b2c3.js（内容变了文件名也变）
  • B. index.html（入口，要能尽快拿到新版本）
  • C. 银行余额接口 GET /api/balance
  • D. 用户上传的头像（可能随时换，但同一 URL）

说出这些指令的含义：max-age · no-cache · no-store · public · private · immutable

查看答案
  • A. public, max-age=31536000, immutable — 文件名变=内容变，旧文件可永久缓存
  • B. no-cache — 入口每次向服务器确认有没有新版本（不是 no-store！）
  • C. no-store — 敏感数据根本不存
  • D. no-cache + ETag 或 URL 加 ?v=169999

指令速记：

  • no-cache → 可存，但每次用前必须协商验证
  • no-store → 完全不存
  • immutable → 配合 hash 文件名，期内绝不重新验证

三、协商缓存

必练

Q3 · 304 场景

📌 场景

logo.png 第一次访问返回 200，响应头：

Cache-Control: max-age=0
ETag: "abc123"

10 分钟后用户再访问，浏览器会？304 时响应体有内容吗？

查看答案
  1. max-age=0 → 强缓存视为立即过期
  2. 浏览器发 GET，带 If-None-Match: "abc123"
  3. 服务器比对 ETag，未变 → 304 Not Modified，无响应体
  4. 浏览器用本地缓存渲染

ETag vs Last-Modified：ETag 内容级指纹更精确；有 ETag 优先用 ETag。

四、刷新行为

必练

Q4 · 三种刷新有什么不同？

📌 场景

你改了 CSS 但用户说「没看到更新」，先问他怎么刷新的？

  • A. 普通 F5 刷新
  • B. Ctrl+Shift+R 强制刷新
  • C. DevTools 勾选 Disable cache 后刷新
查看答案
  • F5：可能走协商缓存；强缓存未过期的资源仍直接用
  • 强刷：跳过强缓存，带协商头重新验证；仍可能 304
  • Disable cache：开发调试用，每次都拿最新

排查「没看到更新」：

  1. 是否拿到了新 index.html（引用了新 hash 的 JS/CSS？）
  2. CDN 是否缓存了旧 index.html
  3. 是否只改了内容没改 hash

五、项目实战

必练

Q5 · 前端构建产物怎么配缓存？

📌 场景

Vite/Webpack 打包后：

index.html
assets/index-a1b2c3.js
assets/index-d4e5f6.css

为什么 JS/CSS 可以 cache 一年，但改了代码用户仍能拿到新版？

查看答案 
location /assets/ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}
location = /index.html {
  add_header Cache-Control "no-cache";
}

为什么能「缓存一年还能更新」：

  • 内容变 → 构建生成新 hash → index.html 引用新文件名
  • 浏览器请求新 URL，旧文件自然淘汰
  • index.html 不长期强缓存，确保能发现新资源名

这是前端缓存最佳实践，面试高频。

必练

Q6 · HTML / API / 头像分别怎么缓存？

查看答案
资源策略原因
hash 静态资源 强缓存 1 年 + immutable 文件名即版本
index.html no-cache 入口及时更新
REST API no-store 或短时间 no-cache 数据实时/敏感
头像/配置 ETag 协商 或 URL 加版本号 同 URL 内容变

额外了解：Service Worker（PWA 离线）、DNS 缓存、Memory/Disk Cache。
