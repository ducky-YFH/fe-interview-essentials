一、数据类型 & typeof

必练

Q1 · JS 有哪些数据类型？typeof 有什么坑？

📌 场景

接口返回 null 表示「无数据」，你写 if (typeof data === 'object') 想过滤对象， 结果 null 也进来了——为什么？

查看答案

7 种（常考分类）：

  • 基本类型（6）：undefined、null、boolean、number、string、symbol
  • 引用类型（1）：object（含数组、函数、Date、RegExp 等）
  • （ES2020+ 还有 bigint，部分面试会提）

typeof 常见结果：

typeof undefined   // 'undefined'
typeof true        // 'boolean'
typeof 42          // 'number'
typeof 'hi'        // 'string'
typeof Symbol()    // 'symbol'
typeof null        // 'object'  ← 历史 bug，必背
typeof []          // 'object'
typeof {}          // 'object'
typeof function(){}// 'function'

上面场景：typeof null === 'object'，不能单靠 typeof 区分 null 和普通对象。

Q2 · undefined 和 null 区别？什么时候用？

📌 场景

表单字段未填写、接口明确返回「无此用户」、函数无返回值—— 分别该用 undefined 还是 null？

查看答案
undefinednull
含义「未定义 / 缺省」「空值 / 无对象」
典型来源未赋值、缺参、无 return主动赋值表示空
JSON会被省略会序列化为 null

实践建议：

  • 接口约定「没有数据」→ 常用 null
  • 可选链 user?.name 不存在 → undefined
  • 判断两者：val == null 同时匹配 undefined 和 null（少数合理用 == 的场景）

Q3 · 怎么可靠判断数组、null、NaN？

📌 场景

工具函数要处理「可能是数组、可能是类数组 NodeList、可能是 null」的入参—— typeof、instanceof、Array.isArray 怎么选？

查看答案
判断目标推荐写法注意
数组 Array.isArray(val) 跨 iframe 比 instanceof 可靠
null val === null typeof 分不清 null
NaN Number.isNaN(val) NaN === NaN 为 false
纯对象 Object.prototype.toString.call(val) === '[object Object]' 区分 array / date / null 
// 不推荐
[] instanceof Array        // 跨 realm 可能失效
isNaN('abc')               // true，会先转数字

// 推荐
Number.isNaN(NaN)          // true
Number.isNaN('abc')        // false

二、相等性 == vs ===

必练

Q4 · 下面哪些为 true？== 转换规则

📌 场景

Code Review 里有人用 == 比较接口字符串 '0' 和数字 0，能通过但团队规范要求 ===——背后的转换规则是什么？

console.log([] == false);
console.log([] == ![]);
console.log(null == undefined);
console.log('0' == 0);
console.log('' == 0);
console.log(null === undefined);
查看答案

输出：全部 true，最后一条 false

== 规则（简化记忆）：

  1. 类型相同 → 同 ===
  2. null == undefined → true（且只和它俩）
  3. 一边是 number → 另一边转 number（'' → 0，'0' → 0）
  4. 一边是 boolean → 转 number 再比
  5. 一边是 object → 转原始值（[] → '' → 0）

经典：[] == ![] → [] == false → '' == false → 0 == 0

项目建议：默认 ===；仅 val == null 判断 null/undefined 可接受。

必练

Q5 · 值类型 vs 引用类型：赋值后改一个会影响另一个吗？

📌 场景

Redux / Vue 里强调「不要直接改 state」，要返回新对象。 const b = a 后改 b.items.push(1)，a 会变吗？ 

let a = 1;
let b = a;
b = 2;
console.log('number:', a, b);

const obj1 = { items: [1] };
const obj2 = obj1;
obj2.items.push(2);
console.log('object:', obj1.items, obj2.items);
console.log('obj1 === obj2:', obj1 === obj2);
查看答案

输出：

number: 1 2
object: [1, 2] [1, 2]
obj1 === obj2: true
  • 基本类型：存值，b = 2 不影响 a
  • 引用类型：存堆地址，obj2 = obj1 共享同一对象，改内部属性互相影响
  • === 比较引用类型比的是引用地址，不是内容 → [] === [] 为 false

这是浅拷贝 / 不可变数据问题的根源，见 原型链 中对象引用理解。

三、浅拷贝 & 深拷贝

必练

Q6 · 浅拷贝有哪些方式？有什么坑？

📌 场景

表单 defaultValues 要复制一份给编辑态，用展开运算符 { ...defaults } 够吗？用户改了嵌套的 address.city 会不会污染默认值？ 

const defaults = { user: { name: 'Tom' }, tags: ['a'] };
const draft = { ...defaults };

draft.user.name = 'Jerry';
draft.tags.push('b');

console.log('defaults.name:', defaults.user.name);
console.log('defaults.tags:', defaults.tags);
console.log('draft === defaults:', draft === defaults);
查看答案

输出：defaults.name: Jerry，tags: ['a','b']，draft === defaults: false

浅拷贝只复制第一层，嵌套对象/数组仍共享引用。

常见浅拷贝方式：

  • { ...obj }、[...arr]
  • Object.assign({}, obj)
  • arr.slice()、arr.concat()

上面场景：有嵌套字段时要深拷贝，或不可变更新（只替换变了的层级）。

选练

Q7 · JSON.parse(JSON.stringify) 能做深拷贝吗？

📌 场景

快速克隆接口 JSON 响应用于本地编辑，同事写了 JSON.parse(JSON.stringify(data))——哪些字段会丢？

查看答案

会丢失或出问题的：

  • undefined、function、Symbol 键/值
  • Date → 变成字符串
  • RegExp → 变成 {}
  • Map / Set
  • 循环引用 → 直接报错

适用：纯 JSON 数据（接口 DTO）的快速深拷贝。

现代替代：structuredClone(obj)（浏览器/Node 16+），支持 Date、Map、循环引用等，但不支持 function。

必练

Q8 · 手写 deepClone（含循环引用）

📌 场景

配置树节点有 parent 指回父节点（循环引用）， 还要复制 Date 字段——JSON 方案不行，面试要你手写。

查看答案 
function deepClone(value, cache = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (cache.has(value)) return cache.get(value);

  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value);

  const result = Array.isArray(value) ? [] : {};
  cache.set(value, result);

  for (const key of Reflect.ownKeys(value)) {
    result[key] = deepClone(value[key], cache);
  }
  return result;
}

口述要点：

  • 基本类型直接返回
  • WeakMap 记录已拷贝对象，解决循环引用
  • 特殊类型 Date/RegExp 单独处理（加分项）
  • Reflect.ownKeys 包含 Symbol 键（加分项）

Q9 · Object.is 和 === 何时不同？

📌 场景

React 用 Object.is 比较 state 是否变化（类似 === 但有例外）——哪两种情况和 === 不一样？

console.log(NaN === NaN);
console.log(Object.is(NaN, NaN));
console.log(+0 === -0);
console.log(Object.is(+0, -0));
查看答案

输出：

false  true
true   false

Object.is 与 === 仅两处不同：

  • NaN 与 NaN → Object.is 为 true
  • +0 与 -0 → Object.is 为 false

React 18 批处理更新用 Object.is 判断 state 是否变化。

Q10 · 项目里什么时候必须深拷贝？

📌 场景

下面哪些需要深拷贝？哪些浅拷贝 / 不可变更新就够？

  • A. 复制接口 JSON 做表单草稿（纯数据，无嵌套改共享风险时已展平）
  • B. 默认配置 config.theme.colors 给用户自定义主题
  • C. React setState({ ...state, count: 1 }) 只改顶层 count
  • D. 撤销/重做栈里存历史 state 快照
查看答案
场景建议
A 扁平 JSON 浅拷贝或 structuredClone 均可
B 嵌套配置 深拷贝，否则改 colors 污染默认配置
C 只改顶层 浅拷贝 + 替换变更字段即可（React 惯用法）
D 历史快照 深拷贝 或不可变数据结构（Immer），否则撤销互相污染

原则：有没有嵌套共享引用且会独立修改？有 → 深拷贝或按层 immutable 更新。

编译期类型安全见 TypeScript 专题；运行时结构复制是本专题重点。
