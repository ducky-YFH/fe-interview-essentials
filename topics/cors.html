一、基础概念

必练

Q1 · 什么是「同源」？下面哪些算跨域？

📌 场景

页面地址：https://www.example.com:443/app/index.html

  • A. https://www.example.com/api/user
  • B. http://www.example.com/api/user
  • C. https://api.example.com/user
  • D. https://www.example.com:8080/app
  • E. https://sub.example.com/app
查看答案

同源 = 协议 + 域名 + 端口 三者完全相同。

  • A ✅ 同源（路径不同不算跨域）
  • B ❌ 跨域（协议 http ≠ https）
  • C ❌ 跨域（域名 api ≠ www）
  • D ❌ 跨域（端口 8080 ≠ 443）
  • E ❌ 跨域（子域 sub ≠ www）

记忆：换路径没事，换协议/域名/端口就算跨域。

必练

Q2 · 为什么浏览器要同源策略？

📌 场景

你在 bank.com 登录了，又去 evil.com 逛，evil 能直接 fetch('https://bank.com/transfer') 吗？为什么？

查看答案

保护用户数据：防止恶意站点用 JS 读取/操作用户在其他站点的敏感信息（Cookie、DOM、接口响应等）。

evil.com 直接 fetch bank.com：

  • 浏览器会发请求（Cookie 可能自动带上，取决于 SameSite）
  • 但 JS 读不到响应体 → CORS 报错，脚本拿不到转账结果
  • 同源策略 + CORS 是「默认拒绝读，服务端可显式放行」

二、CORS 机制

Q3 · 哪些跨域请求「不会被 CORS 拦」？

📌 场景

页面里放 <img src="https://other.com/pixel.gif"> 能加载吗？
fetch('https://other.com/api') 呢？

查看答案

这些标签的跨域加载不走 XHR CORS 校验（但能力受限）：

<img>、<script>、<link>、<video>、<iframe src> 等

  • pixel.gif 图片能显示（但 JS 拿不到像素数据，canvas 会 taint）
  • fetch / axios / XHR 跨域 → 受 CORS 约束，服务端不配头就报错

面试一句话：「标签引用可以跨域加载资源，Ajax 读响应要 CORS 授权。」

必练

Q4 · 预检请求 OPTIONS

📌 场景

前端 https://app.com 要 POST 到 https://api.com/orders

  • Header: Content-Type: application/json
  • Header: Authorization: Bearer xxx
  • withCredentials: true（要带登录 Cookie）

浏览器实际发了几次请求？顺序是什么？预检请求在干什么？

查看答案

实际：先 OPTIONS（预检），再 POST（正式请求），共 2 次。

带 Authorization、Content-Type 为 application/json 等属于「非简单请求」，浏览器先问服务器「我能不能这样跨域？」。 

Access-Control-Request-Method: POST
Access-Control-Request-Headers: authorization, content-type

预检成功（204/200 + 正确 CORS 头）后，才发真正的 POST。

简单请求（不预检）举例：

  • GET / POST（Content-Type 为 text/plain | multipart/form-data | application/x-www-form-urlencoded）
  • 且没有自定义头（如 Authorization）
必练

Q5 · 上面场景后端要配哪些响应头？

Access-Control-Allow-Origin 能写 * 吗？

查看答案

必须：

Access-Control-Allow-Origin: https://app.com   ← 不能是 *（有 credentials 时）
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization

预检 OPTIONS 也要返回上述头。

常见坑：

  • Allow-Origin 写 * + Credentials true → 浏览器拒绝
  • 只配了 POST 的接口，忘了 OPTIONS 处理 → 预检失败

Q6 · 本地开发跨域怎么解决？

📌 场景

Vue 跑在 localhost:5173，接口在 https://api.prod.com，浏览器报 CORS error。

开发环境怎么解决？上线后怎么解决？为什么生产不推荐 JSONP？

查看答案

开发环境（推荐代理）：

vite.config.ts / webpack devServer.proxy — 浏览器请求 localhost:5173/api → 开发服务器转发到 api.prod.com，对浏览器来说「同源」。

生产环境（推荐 CORS 或同域）：

  • 后端配 CORS 白名单
  • 或 Nginx 反代：www.example.com/api → 内网 api 服务（前后端同域最佳）

JSONP 不推荐：只支持 GET、错误处理差、有 XSS 风险。

location /api/ { proxy_pass https://backend/; }

四、Cookie 跨域

必练

Q8 · 登录态跨子域

📌 场景

登录接口在 auth.example.com 设了 Set-Cookie: token=abc
前端页面在 www.example.com，请求 api.example.com 要带 token。

  • Domain / Path / SameSite 分别影响什么？
  • fetch 要带 Cookie，前端和后端各要配什么？
  • SameSite=None 为什么还要求 Secure？
查看答案

Domain：Set-Cookie: Domain=.example.com → www / api / auth 子域共享

Path：限制哪些路径带 Cookie

SameSite：

  • Strict → 完全跨站不带（最安全）
  • Lax → 顶级导航 GET 可带（默认常见）
  • None → 跨站可带，必须配合 Secure（仅 HTTPS）

fetch 带 Cookie：

  • 前端：fetch(url, { credentials: 'include' })
  • 后端：Access-Control-Allow-Credentials: true + Allow-Origin 必须是具体源
