一、基础概念

必练

Q1 · 什么是原型链？用一句话解释

📌 场景

业务里写 const list = [1, 2, 3]; list.map(x => x * 2)， 但 map 明明定义在 Array.prototype 上， 普通数组实例上并没有 map 方法——为什么能直接调用？

查看答案

原型链：访问对象属性时，若自身没有，就沿 [[Prototype]]（即 __proto__）向上查找， 直到 Object.prototype，再往上是 null，这条链就是原型链。

上面场景：

  1. list 自身没有 map
  2. 沿原型找到 Array.prototype.map
  3. 以 list 为 this 执行

面试口述：

「JS 用原型实现继承和方法共享。实例找不到属性时，就顺着原型链往上找， 所以数组能直接用 Array 上的方法。」

必练

Q2 · prototype、__proto__、constructor 什么关系？

📌 场景

DevTools 里展开一个对象，看到 [[Prototype]]； 控制台输入 obj.__proto__ === Obj.prototype 为 true。 面试常问三者怎么串起来——请画/说清关系。

查看答案 
function Person(name) {
  this.name = name;
}
const p = new Person('Tom');
谁是什么
Person.prototype 构造函数上的「原型对象」，实例共享的方法放这里
p.__proto__ 实例指向原型的链接（标准名 [[Prototype]]）
Person.prototype.constructor 指回 Person 函数本身

核心等式（必背）：

p.__proto__ === Person.prototype
Person.prototype.constructor === Person

记忆：prototype 是函数才有的属性； __proto__ 是实例才有的链接。箭头函数没有 prototype，不能 new。

二、属性查找 & 输出题

必练

Q3 · 改 prototype 会影响所有实例吗？

📌 场景

后台管理系统里用构造函数创建多个 Tab 页实例，方法挂在 Tab.prototype.close 上。上线后要给所有 Tab 加一个 refresh 方法——直接改 Tab.prototype 行不行？ 

function Tab(title) {
  this.title = title;
}
Tab.prototype.close = function () {
  console.log('close', this.title);
};

const a = new Tab('首页');
const b = new Tab('设置');

Tab.prototype.refresh = function () {
  console.log('refresh', this.title);
};

a.close();
a.refresh();
b.refresh();
查看答案

输出：

close 首页
refresh 首页
refresh 设置

原因：a、b 的 __proto__ 都指向同一个 Tab.prototype。 事后给 prototype 加方法，已有实例也能用——这就是「方法共享」的好处。

项目注意：改 prototype 影响所有实例；若只想改某一个，应写在实例自身上（属性遮蔽）。

选练

Q4 · 属性遮蔽（shadowing）输出什么？

📌 场景

用户模型 User 在 prototype 上有默认 role: 'guest'。 某个 VIP 用户实例上单独设置了 role = 'vip'，读属性时走哪一层？ 

function User(name) {
  this.name = name;
}
User.prototype.role = 'guest';

const u1 = new User('Alice');
const u2 = new User('Bob');
u2.role = 'vip';

console.log(u1.role);
console.log(u2.role);
delete u2.role;
console.log(u2.role);
查看答案

输出：

guest
vip
guest

查找顺序：先找自身 → 再找原型链。

  • u1 自身无 role → 找到 prototype 的 guest
  • u2.role = 'vip' 在实例上遮蔽了原型属性
  • delete u2.role 删掉实例属性后，又能看到 prototype 的 guest

面试点：改 obj.prop 默认只改实例；要改共享默认值应改 Constructor.prototype.prop。

三、new & instanceof

必练

Q5 · new 做了什么？手写 myNew

📌 场景

封装业务实体 new Order(id)，内部要初始化实例属性、 绑定原型方法、且当构造函数 return 对象时以 return 为准。 说出 new 四步，并手写简化版。

查看答案

new Fn() 四步：

  1. 创建空对象，其 [[Prototype]] 指向 Fn.prototype
  2. 以该对象为 this 执行构造函数
  3. 若构造函数 return 了对象，则返回该对象
  4. 否则返回步骤 1 创建的对象
function myNew(Fn, ...args) {
  const obj = Object.create(Fn.prototype);
  const result = Fn.apply(obj, args);
  return result !== null && (typeof result === 'object' || typeof result === 'function')
    ? result
    : obj;
}

项目场景：ORM 实体、自定义 Error、工厂类实例化，底层都是这套机制。

必练

Q6 · instanceof 原理 + 手写

📌 场景

API 返回可能是数组或 NodeList，要写工具函数区分「真数组」和类数组； 又要判断 err instanceof ApiError 是否为自定义业务错误。 instanceof 底层怎么判？

查看答案

原理：沿实例的 __proto__ 链查找， 看是否出现过 Constructor.prototype。 

function myInstanceof(obj, Constructor) {
  if (obj === null || (typeof obj !== 'object' && typeof obj !== 'function')) {
    return false;
  }
  let proto = Object.getPrototypeOf(obj);
  const target = Constructor.prototype;
  while (proto) {
    if (proto === target) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}

局限（面试加分）：

  • 跨 iframe / 多 Realm 时，同名构造函数 prototype 不同 → 可能 false
  • 基本类型 'abc' instanceof String 为 false（除非 new String('abc')）
  • 改 __proto__ 可「欺骗」instanceof（了解即可）

替代：真数组用 Array.isArray(arr) 更可靠。

四、继承方式 & 项目选型

必练

Q7 · 几种继承方式怎么选？

📌 场景

组件库提供 BaseWidget（含 init、destroy）， 你要写 DatePicker extends BaseWidget，还要能 DatePicker.prototype instanceof BaseWidget 为 true， 且 destroy 不能被所有子类实例共享同一份闭包状态。 该用哪种继承？

查看答案
方式问题现状
原型链继承 引用类型属性被所有实例共享 ❌ 不推荐单独用
构造函数继承 方法无法复用，都在实例上 ❌ 不推荐单独用
组合继承 父类构造函数调两次 ⚠️ 了解即可
寄生组合继承 只调一次父构造，原型链正确 ✅ ES5 最佳
ES6 class extends 语法糖，本质仍是原型链 ✅ 现代项目首选

上面场景答案：现代代码直接 class DatePicker extends BaseWidget；ES5 环境用寄生组合。

function inherit(Child, Parent) {
  Child.prototype = Object.create(Parent.prototype);
  Child.prototype.constructor = Child;
}
选练

Q8 · 寄生组合继承完整写法

📌 场景

维护老项目（无 class 语法），要实现 Animal → Dog，Dog 有自己的 breed， 又能调用 Animal 的 eat。

查看答案 
function Animal(name) {
  this.name = name;
}
Animal.prototype.eat = function () {
  console.log(this.name, 'eating');
};

function Dog(name, breed) {
  Animal.call(this, name); // 继承实例属性
  this.breed = breed;
}
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;
Dog.prototype.bark = function () {
  console.log('wang');
};

const d = new Dog('Rex', 'husky');
d.eat();  // Rex eating
d.bark(); // wang

两步记忆：

  1. Parent.call(this, ...) — 拷贝父类实例属性
  2. Child.prototype = Object.create(Parent.prototype) — 链上共享方法
选练

Q9 · Object.create 在项目里怎么用？

📌 场景

解析 URL query 得到键值对字典 params，要用 params.toString 做 key 却意外命中了 Object.prototype.toString——怎么创建「干净」的纯字典对象？

查看答案 
// ❌ 有原型污染风险
const bad = {};
bad['toString'] = 'oops'; // 可能和原型方法冲突

// ✅ 无原型对象（纯字典）
const params = Object.create(null);
params.foo = 'bar';
params.toString = 'safe-key'; // 不会碰到 Object.prototype

其他场景：

  • myNew 里 Object.create(Fn.prototype)
  • 以现有对象为模板创建新对象（浅拷贝 + 指定原型）
  • 实现继承时替代直接改 prototype

Q10 · jQuery 插件 / Vue mixin 的本质

📌 场景

写 jQuery 插件 $.fn.tooltip = function() { ... }， 所有 $('div') 都能 .tooltip()。 这和原型链什么关系？Vue2 的 mixins: [logMixin] 又是另一种「继承」吗？

查看答案

jQuery：

// jQuery 实例 arr = [dom1, dom2, ...]
// arr.__proto__ === $.fn === jQuery.prototype
$.fn.tooltip = function () { /* this 是每个 jQuery 集合 */ };

给 $.fn 挂方法 = 改 jQuery.prototype，所有 jQuery 实例共享。

Vue2 mixin：不是原型链继承，是编译/选项合并——把 data、methods、生命周期钩子合并进组件选项。理解「共享行为」的另一种实现即可。

面试答法：「插件挂 prototype 是典型方法共享；框架 mixin 是选项合并，动机类似，机制不同。」

选练

Q11 · class 只是语法糖吗？

📌 场景

TS/Babel 编译后的 class Admin extends User 在 IE11 里长什么样？ 为什么说 class 没有提升（hoisting）？

查看答案 
class User {
  constructor(name) { this.name = name; }
  sayHi() { console.log(this.name); }
}

class Admin extends User {
  constructor(name, role) {
    super(name);
    this.role = role;
  }
}

本质：

  • 方法挂在 User.prototype 上（非 enumerable，与手写不同）
  • extends 编译后 ≈ 寄生组合 + super 调用父构造
  • class 声明在 TDZ 内，不能先于声明使用（不像 function 声明会提升）

与箭头函数专题联动：class 方法若写成箭头函数属性，则挂在实例上、this 词法绑定，适合 React 类组件传回调。

Q12 · hasOwnProperty vs in · 遍历对象

📌 场景

要把接口 JSON 里所有字段渲染成表单，写 for (const key in obj) 却多出了 toString、constructor 等键——为什么？怎么只遍历自身字段？

查看答案 
const user = { id: 1, name: 'Tom' };

// in：自身 + 原型链上 enumerable 的属性
'id' in user;           // true
'toString' in user;     // true（来自 Object.prototype）

// hasOwnProperty：仅自身
user.hasOwnProperty('id');       // true
user.hasOwnProperty('toString');  // false

安全遍历自身属性：

Object.keys(user);                        // 推荐
Object.getOwnPropertyNames(user);
for (const key of Object.keys(user)) { ... }

现代写法：Object.hasOwn(obj, key) 替代 obj.hasOwnProperty(key)，避免 obj 上没有 hasOwnProperty 或被覆盖。
