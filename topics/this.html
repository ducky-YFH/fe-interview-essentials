一、四种绑定规则

必练

Q1 · this 怎么确定？四种规则 + 优先级

📌 场景

面试常问：「你说一下 this 指向」。要能快速讲清四种情况， 并知道 new 和 bind 谁优先。

查看答案
规则条件this 指向
1. 默认绑定 独立函数调用 fn() 非严格模式 → 全局对象；严格模式 → undefined
2. 隐式绑定 obj.fn()，调用点在前面的对象 obj
3. 显式绑定 fn.call(obj) / apply / bind 传入的第一个参数（绑定对象）
4. new 绑定 new Fn() 新创建的实例对象

优先级（高 → 低）：

new 绑定 > 显式 bind > 隐式绑定 > 默认绑定

例外：箭头函数没有自己的 this，捕获定义时的外层 this，不适用以上四条（见 Q6）。

面试口述模板：「看调用方式：谁点出来的、call 传了谁、是不是 new；箭头函数看定义位置。」

选练

Q2 · 默认绑定：独立调用输出什么？

📌 场景

工具函数 log() 里打了 this，在模块顶层直接 log() 和在对象里 obj.log() 行为不同——为什么？ 

function log() {
  'use strict';
  console.log('strict this:', this);
}

log();

const obj = { name: 'app', log };
obj.log();
查看答案

输出（浏览器）：

  • log() 严格模式 → strict this: undefined
  • obj.log() → 隐式绑定，this 为 obj 对象

非严格模式独立调用时 this 为 window（浏览器）或 global（Node）。

现代工程多开严格模式 / 模块自动严格，独立调用 this 为 undefined 很常见。

二、隐式绑定丢失（高频坑）

必练

Q3 · 把方法当回调传，this 为什么丢了？

📌 场景

用户对象有 user.getName()，你把 user.getName 传给 Array.prototype.map 或 setTimeout， 结果 this.name 报错或变成 undefined。 

const user = {
  name: 'Alice',
  getName() {
    return this.name;
  },
};

console.log('direct:', user.getName());

const fn = user.getName;
try {
  console.log('assigned:', fn());
} catch (e) {
  console.log('assigned error:', e.message);
}

console.log('map:', [user].map(user.getName));
查看答案

原因：判断 this 看调用点，不是定义位置。

  • user.getName() → 隐式绑定，this 是 user ✅
  • const fn = user.getName; fn() → 独立调用，默认绑定，严格模式 this 为 undefined ❌
  • map(user.getName) → 由 map 内部调用，this 可能是 undefined 或数组相关对象 ❌

修复：

// 1. 箭头包装
items.map(() => user.getName());

// 2. bind
setTimeout(user.getName.bind(user), 0);

// 3. 显式 call（立即调用时）
user.getName.call(user);
必练

Q4 · call / apply / bind 区别与使用场景

📌 场景
  • A. 借用数组方法处理类数组 arguments
  • B. 继承时调用父构造函数 Parent.call(this, args)
  • C. 事件回调要固定组件实例 this
查看答案
方法行为参数
call 立即调用，指定 this 参数列表逐个传
apply 立即调用，指定 this 参数数组
bind 返回新函数，不立即调用 可预设 this + 部分参数 
// A. 借用
const args = Array.prototype.slice.call(arguments);

// B. 继承（ES5）
function Child() {
  Parent.call(this, name);
}

// C. 固定 this
button.addEventListener('click', this.handleClick.bind(this));

记忆：要立即执行用 call/apply；要传给别处稍后执行用 bind。

三、new 绑定 & 箭头函数

Q5 · new 调用时 this 是谁？

📌 场景

用构造函数 new User('Tom') 创建实例， 构造函数里的 this.name = name 中的 this 指向哪里？ 若构造函数 return 了普通对象会怎样？ 

function User(name) {
  this.name = name;
  // return { hijack: true }; // 取消注释试试
}

const u = new User('Tom');
console.log(u.name);
console.log(u instanceof User);
查看答案

new 时 this = 新创建的空对象（已链上 Fn.prototype）。

return 规则：

  • return 基本类型 / 无 return → 返回新对象 u
  • return 对象 → 用该对象替换默认返回值（hijack 对象）

与 原型链 Q5 的 myNew 手写题联动记忆。

必练

Q6 · 箭头函数的 this 能用 call 改吗？

📌 场景

对象字面量里写 arrow: () => this.x 想访问对象属性， 却发现 this 不是对象本身——和类里写普通方法有何不同？ 

const obj = {
  x: 10,
  regular() {
    return this.x;
  },
  arrow: () => this.x,
};

console.log('regular:', obj.regular());

const bound = obj.arrow.bind(obj);
console.log('arrow:', obj.arrow(), 'bound:', bound());
查看答案

结论：

  • regular() → 隐式绑定，返回 10
  • arrow 捕获定义时外层 this（浏览器全局或 undefined），bind/call 无效

项目规则：

  • 对象方法需要 this 指对象 → 用普通方法 / 简写 method() {}
  • 回调要捕获外层 this（如 React 类组件）→ 箭头函数或 bind

更多输出题见 箭头函数专题。

Q7 · 多层对象 + 赋值输出

📌 场景

嵌套对象把内层方法赋给变量再调用——考察隐式绑定与引用传递。

var name = 'global';

const a = {
  name: 'a',
  func() {
    console.log(this.name);
  },
};

const b = { name: 'b' };
b.func = a.func;
b.func();

(a.func)();
查看答案

输出：b，然后 a

  • b.func() → 调用点是 b，this 是 b
  • (a.func)() → 括号不改变调用点，仍是 a.func()，this 是 a

坑：以为 func 从 a 来就指向 a——错，只看谁调用。

选练

Q8 · 手写 myBind（简化版）

📌 场景

面试追问：「bind 原理是什么？」——能写简化版即可，注意 new 调用时 this 要指向实例。

查看答案 
Function.prototype.myBind = function (context, ...preset) {
  const fn = this;
  return function bound(...args) {
    // new 调用时不能强行绑 context
    const isNew = this instanceof bound;
    return fn.apply(
      isNew ? this : context,
      preset.concat(args)
    );
  };
};

要点：

  • 返回新函数，延迟执行
  • 支持预设参数（偏函数）
  • new bound() 时忽略 bind 的 context，this 指向新实例

Q9 · DOM 事件 / React 类组件 this 丢失

📌 场景
// React 类组件（简化）
class Page extends React.Component {
  state = { count: 0 };

  handleClick() {
    this.setState({ count: this.state.count + 1 });
  }

  render() {
    return <button onClick={this.handleClick}>+1</button>;
  }
}

点击按钮报错 Cannot read properties of undefined (reading 'setState')——为什么？几种修法？

查看答案

原因：onClick={this.handleClick} 把方法当值传递，点击时独立调用，this 丢失（严格模式为 undefined）。

修法（任选）：

  1. 构造函数里 this.handleClick = this.handleClick.bind(this)
  2. 类字段箭头函数 handleClick = () => { this.setState(...) }
  3. 内联箭头 onClick={() => this.handleClick()}（每次 render 新函数，注意性能）

原生 DOM：

btn.addEventListener('click', this.handleClick.bind(this));
// 或
btn.addEventListener('click', () => this.handleClick());

Vue 2：methods 里不要用箭头函数定义方法，否则 this 不是组件实例。

Q10 · setInterval / 定时器里 this 错了怎么改？

📌 场景
const counter = {
  count: 0,
  run() {
    setInterval(function () {
      this.count++;
      console.log(this.count);
    }, 100);
  },
};
counter.run(); // NaN 或报错

倒计时组件里 this.count 一直 NaN——一行怎么修？

查看答案

原因：setInterval 回调是独立函数调用，默认绑定，this 不是 counter。

修法：

// 1. 箭头函数（推荐）
setInterval(() => {
  this.count++;
  console.log(this.count);
}, 100);

// 2. bind
setInterval(function () {
  this.count++;
}.bind(this), 100);

// 3. 存 self（老写法）
const self = this;
setInterval(function () {
  self.count++;
}, 100);

同 箭头函数 Q16，这里从 this 四规则角度理解。
