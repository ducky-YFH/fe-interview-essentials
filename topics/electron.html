一、进程模型

必练

Q1 · 主进程、渲染进程、preload 各做什么？

📌 场景

猫咔大师 Electron 工作台：窗口菜单、本地目录扫描、缩略图生成在「某处」； Vue 页面在「另一处」——三者职责怎么划分？

查看答案
角色职责能否直接操作 DOM
主进程 Main 应用生命周期、创建窗口、系统 API、原生模块（fs、Sharp、spawn Python） ❌
渲染进程 Renderer 每个窗口里的 Web 页面（你的 Vue 应用） ✅
preload 在页面加载前注入，通过 contextBridge 向渲染层暴露受控 API 可访问部分 Node，但不直接改 UI

记忆：一个 Electron 应用一个主进程；每个 BrowserWindow 一个渲染进程；preload 是渲染进程里、页面脚本运行前的桥梁。

Q2 · IPC 怎么通信？invoke / send 区别？

📌 场景

渲染层要选本地文件夹、等主进程扫完返回文件列表，还要监听 AI 聚类进度—— 用哪种 IPC 模式？

查看答案

两种常见模式：

模式渲染 → 主特点
异步请求/响应 ipcRenderer.invoke('channel', args) 返回 Promise，适合「要结果」的操作（扫目录、读文件）
单向 + 事件 ipcRenderer.send / 主进程 webContents.send 适合通知、进度推送（上传进度、AI 任务状态） 
// preload
contextBridge.exposeInMainWorld('electronAPI', {
  scanDir: (path) => ipcRenderer.invoke('fs:scan', path),
  onAiProgress: (cb) => ipcRenderer.on('ai:progress', (_, p) => cb(p)),
});

// main
ipcMain.handle('fs:scan', async (_, dir) => { /* ... */ });

原则：渲染层不直接 require('fs')，统一走 preload 白名单 API。

必练

Q3 · contextIsolation、nodeIntegration 怎么配？

📌 场景

为了省事有人设 nodeIntegration: true，页面里能直接 require('child_process')——为什么生产环境危险？推荐配置是什么？

查看答案

风险：渲染进程加载的远程页面 / XSS 一旦执行，可直接调用 Node → 读文件、执行系统命令。

现代推荐（Electron 安全清单）：

webPreferences: {
  contextIsolation: true,   // 隔离 preload 与页面 JS 上下文
  nodeIntegration: false,   // 页面不能 require
  sandbox: true,            // 渲染进程沙箱（视版本与需求）
  preload: path.join(__dirname, 'preload.js'),
}
  • contextIsolation: true — 页面拿不到 Node，只能通过 contextBridge 暴露的 API
  • nodeIntegration: false — 禁止页面脚本直接 require
  • 禁用 remote 模块（已废弃）
  • 加载外部 URL 时格外谨慎 CSP

面试答法：「最小权限：主进程干重活，preload 白名单暴露，渲染层当普通 Web。」

Q4 · preload 如何设计「受控文件 API」？

📌 场景

需要：选目录、递归扫描、批量复制、打开系统文件夹、检测文件是否存在。 渲染层 Vue 组件该怎么调用？preload 要暴露哪些方法？

查看答案

设计原则：

  • 只暴露业务需要的方法，不暴露整个 fs / path
  • 主进程校验路径（禁止任意路径读写、防 ../ 穿越）
  • 返回可序列化数据（路径字符串、文件元信息），大文件用流或分片
// preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('desktop', {
  pickDirectory: () => ipcRenderer.invoke('dialog:pickDir'),
  scanDirectory: (dir) => ipcRenderer.invoke('fs:scan', dir),
  copyFiles: (items) => ipcRenderer.invoke('fs:copy', items),
  revealInFolder: (filePath) => ipcRenderer.invoke('shell:show', filePath),
});

Vue 侧：封装 useDesktopFiles() composable，内部调 window.desktop，与 Web 版 adapter 切换。

三、性能 & 本地能力

必练

Q5 · 为什么用 Sharp 在主进程生成缩略图？

📌 场景

底片墙直接 <img src="file:///.../50MB.jpg"> 导致窗口卡顿—— 你们改为主进程 Sharp 出缩略图再给渲染层，原因是什么？

查看答案

原因：

  • 大图解码占 CPU/内存，放渲染进程会阻塞 UI 线程，滚动掉帧
  • Sharp（libvips）在主进程批量生成小图，渲染层只加载几百 KB 缩略图
  • 原生模块（.node）通常放主进程更稳，避免多窗口重复加载
  • 可提供 Electron 原生解码兜底，统一 IPC 接口

流程：扫目录 → 主进程队列生成 thumb → 返回 thumb 路径或 base64 → Vue 虚拟列表展示。

渲染优化见 渲染&性能、Vue3 Q11。

Q6 · 大量本地文件扫描如何不卡 UI？

📌 场景

摄影师一次导入 2 万张 JPG+RAW，递归扫盘、算 MD5、匹配文件名—— 主进程也不能一次同步跑完，你怎么调度？

查看答案
  • 分批 / 流式：目录遍历用异步 API，每 N 个文件 yield 或发进度事件
  • Worker 线程：worker_threads 处理 MD5、匹配，不堵主进程事件循环
  • 并发限制：MD5/复制用线程池，避免把磁盘打满（链 并发 Q5）
  • 可取消：任务 id + AbortSignal，用户换目录时停掉旧任务
  • 增量结果：IPC 推送已扫描列表，UI 边扫边展示

Q7 · Web 与 Electron 共用一套 Vue 代码怎么拆？

📌 场景

Monorepo 里 Web 版不能访问本地文件，Electron 版要扫盘—— 业务组件如何不写两份？

查看答案

Adapter 模式：

// packages/platform
export interface FilePlatform {
  pickDirectory(): Promise<string | null>;
  scanDirectory(dir: string): Promise<FileEntry[]>;
}

// app-web: 仅上传 input，无本地扫盘
// app-electron: 调 window.desktop

// Vue 组件
const platform = inject<FilePlatform>('filePlatform');

与 Vue3 Q12 Monorepo 同一套思路：逻辑在 composables，平台能力注入。

Q8 · IPC 接入 Python / InsightFace，任务状态怎么设计？

📌 场景

AI 人脸聚类：模型缺失要下载、解压、初始化、Busy 重试、用户取消、失败提示—— 主进程跑 Python，渲染层 Pinia 怎么接？

查看答案

主进程：

  • child_process.spawn 或常驻 Python 子进程
  • stdio / socket 传 JSON 行协议，或进度通过 IPC 转发
  • 维护 TaskManager：单例任务、cancel token、kill 子进程

状态机（与简历一致）：

idle → model_missing → downloading → extracting
  → initializing → running → success | failed | cancelled

渲染层：

  • Pinia store 存 aiTask 状态 + 进度
  • onAiProgress 订阅 IPC 更新 UI
  • 取消按钮 → invoke('ai:cancel') → 主进程终止子进程

面试亮点：「重活和模型都在主进程/子进程，渲染层只做状态流和结果展示。」

Q9 · 自动更新、打包、环境变量要注意什么？

📌 场景

electron-builder 打包 Win/Mac，内嵌 Python 模型包体积很大——面试可能问发布与更新策略。

查看答案
  • 打包：electron-builder / forge；asar 打包应用代码；原生模块要 rebuild
  • 大资源：模型放 extraResources，首启或按需下载（你项目里的 model_missing 流程）
  • 自动更新：electron-updater + 发布服务器；注意签名（Mac notarize）
  • 环境：区分 dev / prod API；敏感配置不进渲染层
  • 安全：更新包 HTTPS + 签名校验

了解即可，结合你「模型下载、解压」经历讲按需分发更加分。

同一套 IM 封装，Web 用 WASM SDK，Electron 用原生 SDK—— 登录、会话、未读、已读回执接口要统一，你会怎么抽象？

interface ImClient {

  getConversationList(): Promise<Conversation[]>;
  sendTextMessage(convId: string, text: string): Promise<void>;
  onUnreadChange(cb: (n: number) => void): () => void;

// im-web-wasm / im-electron 各实现
// Pinia chatStore 只依赖 ImClient 接口

注意：Electron 下 SDK 初始化可能在主进程或渲染进程（看官方文档）；断线重连、心跳、token 刷新逻辑放 composable 统一处理。
