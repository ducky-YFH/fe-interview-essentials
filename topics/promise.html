一、基础概念

必练

Q1 · Promise 有哪三种状态？状态可以怎么变？

查看答案
  • pending（进行中）
  • fulfilled（已成功）
  • rejected（已失败）

状态变化：

  • pending → fulfilled（调用 resolve）
  • pending → rejected（调用 reject）
  • 状态一旦变更就不可逆，不能再变

原因：Promise 是对「单次异步结果」的抽象，settled 后结果应稳定。

选练

Q2 · 下面说法哪些正确？

📌 场景
  • A. Promise 创建后 executor 会立即执行
  • B. resolve 之后还能再 reject
  • C. .then 的回调一定在微任务队列里执行
  • D. .catch 只能捕获前一个 .then 里的错误
查看答案
  • A ✅ executor 在 new Promise 时同步执行
  • B ❌ resolve 后再 reject 无效，状态已锁定
  • C ✅ .then/.catch/.finally 注册的回调进微任务（浏览器里一般是 microtask queue）
  • D ❌ .catch 能捕获链上前面任意环节未处理的 rejection（类似冒泡）
选练

Q3 · Promise 和回调函数相比，解决了哪些问题？又带来了什么新问题？

查看答案

解决：

  • 回调地狱 → 链式 .then 扁平化
  • 错误处理分散 → .catch 统一捕获
  • 难以组合多个异步 → all/race/any 等

新问题：

  • 链路过长可读性仍差 → async/await 缓解
  • 忘记 return 导致后续 then 提前执行
  • unhandled rejection
  • 调试栈不如同步代码直观
必练

Q4 · 下面代码输出什么？顺序是什么？

📌 场景
console.log('1');
new Promise((resolve) => {
  console.log('2');
  resolve('ok');
  console.log('3');
}).then((val) => console.log('4', val));
console.log('5');
查看答案

输出顺序：1 → 2 → 3 → 5 → 4 ok

原因：

  • new Promise 里 executor 同步执行 → 2、3
  • resolve 只改变状态，then 回调进微任务
  • 同步代码 5 先跑完
  • 本轮宏任务清空后进微任务 → 4 ok
选练

Q5 · .then / .catch / .finally 各自什么时候执行？finally 里 return 值会影响链式结果吗？

查看答案
  • then(onFulfilled)：上一环 fulfilled 时执行；onFulfilled 抛错 → 下一环 rejected
  • catch(onRejected)：捕获 rejected；返回新 fulfilled Promise（除非 catch 里再抛错）
  • finally(onFinally)：无论成功失败都执行；不接收上一环的值作参数

finally 的 return：

  • 若 finally 没有 return 或 throw，会「透传」上一环的结果
  • 若 finally return 了值，会覆盖链的结果（fulfilled）
  • 若 finally throw，链变 rejected

Q6 · 下面每段输出什么？

📌 场景

6a：

Promise.resolve(1)
  .then((x) => x + 1)
  .then((x) => { throw new Error('fail'); })
  .then((x) => console.log('6a-never', x))
  .catch((e) => console.log('6a-catch', e.message))
  .then(() => console.log('6a-after-catch'));

6b：

Promise.resolve(1)
  .then((x) => Promise.resolve(x + 1))
  .then((x) => console.log('6b', x));

6c：

Promise.resolve(1)
  .then((x) => ({ value: x }))
  .then((x) => console.log('6c', x, typeof x));
查看答案

6a：

6a-catch fail
6a-after-catch

throw 后跳过后面的 then，进 catch；catch 处理完默认返回 fulfilled，所以 after-catch 仍执行。

6b：6b 2

return Promise.resolve(2) 会被「展平」，下一 then 收到 2 不是 Promise 对象。

6c：6c { value: 1 } object

return 普通对象，下一 then 直接收到该对象。

Q8 · 错误在 Promise 链中如何传递？下面哪些写法能捕获到 error？

📌 场景
const p = Promise.reject(new Error('boom'));

// p.then((v) => console.log(v)).catch((e) => console.log('8a', e.message));
// p.catch((e) => console.log('8b', e.message));
// p.then(null, (e) => console.log('8c', e.message));
// try { await p; } catch (e) { console.log('8d', e.message); }
查看答案

能捕获：

  • 8b p.catch(...)
  • 8c p.then(null, onRejected) — 第二个参数形式
  • 8d await + try/catch

8a 只有 then 没有 catch → unhandled rejection（除非外层还有 catch）

规则：rejection 会跳过中间没有 onRejected 的 then，直到遇到 catch 或 then 的第二个参数。

Q9 · 经典输出顺序题

📌 场景
console.log('A');

setTimeout(() => console.log('B'), 0);

Promise.resolve()
  .then(() => console.log('C'))
  .then(() => console.log('D'));

console.log('E');
查看答案

顺序：A → E → C → D → B

同步 A E → 微任务 C D → 宏任务 B（setTimeout）

选练

Q10 · 更复杂的一题

📌 场景
console.log('start');

setTimeout(() => {
  console.log('timeout1');
  Promise.resolve().then(() => console.log('promise-in-timeout'));
}, 0);

Promise.resolve()
  .then(() => {
    console.log('promise1');
    setTimeout(() => console.log('timeout2'), 0);
  })
  .then(() => console.log('promise2'));

console.log('end');
查看答案

顺序：start → end → promise1 → promise2 → timeout1 → promise-in-timeout → timeout2

  1. 同步 start end
  2. 微任务 promise1，其 then 注册 setTimeout(timeout2)
  3. 微任务 promise2
  4. 宏任务 timeout1，内部 then 注册微任务 promise-in-timeout
  5. 微任务 promise-in-timeout
  6. 宏任务 timeout2

面试答法：先同步，再清空微任务，再取一个宏任务，循环。

选练

Q11 · async/await 和 Promise.then 在调度上有什么关系？下面输出顺序？

📌 场景
async function q11() {
  console.log('11-1');

  await Promise.resolve();
  console.log('11-2');

  Promise.resolve().then(() => console.log('11-3'));

  console.log('11-4');
}
查看答案

顺序：11-1 → 11-2 → 11-4 → 11-3

  • await 之前同步执行 → 11-1
  • await Promise.resolve() 已 fulfilled，await 之后的代码整体作为微任务调度
  • 该微任务内顺序执行：11-2 → 注册 11-3 的微任务 → 11-4
  • 微任务队列下一轮 → 11-3

记忆：await = 「把后面代码包进 .then」；await 后的同步代码仍在同一微任务里顺序跑完。

必练

Q12 · Promise.all / Promise.race / Promise.allSettled / Promise.any 各自语义？入参有 rejected 时行为？

查看答案
方法 成功条件 失败条件
Promise.all 全部 fulfilled 任一 rejected → 立即 reject
Promise.race 第一个 settled 第一个 settled 若是 reject 则 reject
Promise.allSettled 全部 settled 永不 reject，返回每项 status 结果
Promise.any 任一 fulfilled 全部 rejected → AggregateError
选练

Q13 · 下面输出什么？

📌 场景
const slow = new Promise((r) => setTimeout(() => r('slow'), 100));
const fast = Promise.resolve('fast');
const fail = Promise.reject(new Error('fail'));

Promise.race([slow, fast, fail]).then(console.log).catch(console.log);
Promise.any([fail, Promise.reject('x')]).then(console.log).catch(console.log);
Promise.allSettled([fast, fail]).then(console.log);
查看答案
  • race([slow, fast, fail]) → 很快 reject Error('fail')（fail 最先 settled）
  • any([fail, reject('x')]) → reject AggregateError（全部失败）
  • allSettled([fast, fail]) → [{status:'fulfilled',value:'fast'},{status:'rejected',reason:...}]
选练

Q14 · Promise.all 里某个 promise 抛错，其他还在执行的会怎样？需要写 abort / 取消逻辑吗？

查看答案

某个 rejected 后，Promise.all 立即 reject，但其他 promise 仍在运行，不会被自动 abort。

若需节省资源，应自己实现 AbortController / 标志位 / 可取消封装。

必练

Q15 · 实现 promiseAll(promises)

手写 promiseAll，语义与 Promise.all 一致。

查看答案 
function promiseAll<T>(promises: Array<T | PromiseLike<T>>): Promise<T[]> {
  return new Promise((resolve, reject) => {
    const result: T[] = [];
    let count = 0;
    const len = promises.length;
    if (len === 0) return resolve([]);
    promises.forEach((p, i) => {
      Promise.resolve(p).then(
        (val) => {
          result[i] = val;
          if (++count === len) resolve(result);
        },
        reject
      );
    });
  });
}

Q18 · await 后面跟非 Promise 值会怎样？await 1 和 await Promise.resolve(1) 有区别吗？

查看答案

必练

Q19 · 如何在 async 函数里「串行」执行多个异步任务？如何「并行」执行？各有什么性能差异？

📌 场景
const tasks = [
  () => new Promise((r) => setTimeout(() => r(1), 100)),
  () => new Promise((r) => setTimeout(() => r(2), 100)),
  () => new Promise((r) => setTimeout(() => r(3), 100)),
];
查看答案

串行（总耗时累加）：

for (const task of tasks) {
  await task();
}

并行（总耗时≈最慢那个）：

await Promise.all(tasks.map((t) => t()));

注意：forEach 里写 await 不会串行等待，因为 forEach 回调不是 async 语义上的串行循环。

六、场景&坑

选练

Q21 · 什么是 unhandled promise rejection？如何避免？

查看答案

Promise reject 后没有任何 .catch / try-await-catch 处理。

  • Node：process.on('unhandledRejection')
  • 浏览器：unhandledrejection 事件

避免：链末尾 .catch；async 里 try/catch；全局兜底监听。

选练

Q22 · Promise.resolve(p) 和 new Promise(r => r(p)) 一样吗？如果 p 本身是 rejected Promise 呢？

查看答案

若 p 是 thenable/Promise：

  • Promise.resolve(p) 会展开 p，跟随其最终状态（fulfilled 或 rejected）
  • new Promise(r => r(p)) 若 p rejected，r(p) 会把外层也 reject（类似展平）

二者对 thenable 行为类似，但 Promise.resolve 是标准静态方法，更常用。

必练

Q23 · 下面有什么问题？如何改？

📌 场景
fetchUser()
  .then((user) => {
    fetchOrders(user.id); // 漏写 return
  })
  .then(() => {
    console.log('orders loaded'); // 会等 fetchOrders 完成吗？
  });
查看答案

orders loaded 会在 fetchUser 完成后几乎立刻打印，不会等 fetchOrders。

因为 then 里没有 return fetchOrders(...)，下一 then 收到 undefined 且不会等待。

修复：

.then((user) => fetchOrders(user.id))

Q24 · 实现带并发限制的请求调度器

例如：最多同时 3 个请求，完成一个再补下一个。

查看答案 
async function runPool<T>(
  tasks: (() => Promise<T>)[],
  limit: number
): Promise<T[]> {
  const results: T[] = new Array(tasks.length);
  let index = 0;

  async function worker() {
    while (index < tasks.length) {
      const cur = index++;
      results[cur] = await tasks[cur]();
    }
  }

  const workers = Array.from({ length: Math.min(limit, tasks.length) }, () =>
    worker()
  );
  await Promise.all(workers);
  return results;
}

Q25 · 实现 sleep(ms) 和 timeout(promise, ms)

查看答案 
function sleep(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function timeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  return Promise.race([
    promise,
    sleep(ms).then(() => Promise.reject(new Error('timeout'))),
  ]);
}

Q26 · 如何用 Promise 实现 retry(fn, times)？

查看答案 
async function retry<T>(
  fn: () => Promise<T>,
  times: number,
  delay = 0
): Promise<T> {
  let lastError: unknown;
  for (let i = 0; i < times; i++) {
    try {
      return await fn();
    } catch (e) {
      lastError = e;
      if (i < times - 1 && delay > 0) {
        await new Promise((r) => setTimeout(r, delay));
      }
    }
  }
  throw lastError;
}
