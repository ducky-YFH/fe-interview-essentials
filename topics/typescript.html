一、类型推断 & 基础

必练

Q1 · 下面变量/表达式的类型分别是什么？

📌 场景
let a = 'hello';
const b = 'hello';
let c = [1, 'two'];
const d = [1, 'two'] as const;

a、b、c、d 的类型分别是什么？

查看答案
  • a: string
  • b: 'hello'（字面量类型）
  • c: (string | number)[]
  • d: readonly [1, 'two']

原因：

  • let a 允许重新赋值，推断为 string，不会收窄成字面量
  • const b 不会重新赋值，收窄为字面量 'hello'
  • let c 元素类型不固定，推断为可变数组 (string | number)[]
  • as const 表示深只读 + 字面量，变成固定长度元组，不能 push/pop
选练

Q2 · 哪行会报编译错误？为什么？

📌 场景
let x: string = 'hi';
x = 1;

const arr: readonly number[] = [1, 2, 3];
arr.push(4);

const obj = { name: 'Tom' as const };
obj.name = 'Jerry';
查看答案

三行都会报错。

  • x = 1 — x 声明为 string，赋 number 违反类型约束
  • arr.push(4) — readonly number[] 只读，禁止修改
  • obj.name = 'Jerry' — name: 'Tom' as const 锁死为字面量，不能再赋
选练

Q3 · 函数返回值类型是什么？

📌 场景
function fn(flag: boolean) {
  if (flag) return 1;
  return 'no';
}

fn 的返回类型是什么？

查看答案

string | number

TS 分析所有 return 分支，合并可能返回的类型：

  • flag 为 true → return 1（number）
  • flag 为 false → return 'no'（string）

所以返回值是 string | number，不是 any。

选练

Q4 · 以下赋值哪些合法？

📌 场景
const n1: number = null;
const n2: number | null = null;
const u: undefined = null;
const v: void = undefined;
查看答案
  • n1: number = null → ❌ 报错（strictNullChecks 开启时）
  • n2: number | null = null → ✅ 合法
  • u: undefined = null → ❌ 报错（null 和 undefined 是不同类型）
  • v: void = undefined → ✅ 合法

原因：strictNullChecks 下 null/undefined 不能隐式赋给 number 等普通类型，必须显式写 number | null。void 表示「无有意义返回值」，允许赋 undefined。

二、interface vs type

必练

Q5 · interface 和 type 的区别？各举适合场景。

查看答案
能力 interface type
声明合并 ✅ 可以 ❌ 同名会冲突
联合类型 ❌ 不行 ✅ string | number
映射/条件类型 ❌ 不行 ✅ 工具类型常用
extends 继承 ✅ 直观 ✅ 用交叉类型 &

场景：

  • 定义 API / 组件 props 对象 → interface
  • 联合类型、工具类型、复杂变换 → type

interface 支持同名自动合并（方便扩展第三方库类型）；type 更灵活，能表达联合、交叉、条件、映射等复杂类型。

必练

Q6 · 下面哪种写法可以声明合并（Declaration Merging）？

📌 场景
interface UserA { name: string; }
interface UserA { age: number; }  // 能否合并？

type UserB = { name: string };
type UserB = { age: number };    // 能否合并？
查看答案
  • interface UserA { age: number } → ✅ 可以合并，最终 UserA 有 name + age
  • type UserB = { age: number } → ❌ 报错：Duplicate identifier 'UserB'

原因：Declaration Merging 是 interface 专有特性，多个同名 interface 自动合并。type 只是别名，重复声明等于定义两个同名类型，编译器不允许。

必练

Q7 · 以下 extends 与 & 等价吗？有何坑？

📌 场景
interface A7 { id: number; }
interface B7 { id: string; name: string; }
type C7 = A7 & B7;  // id 是什么类型？
查看答案

id 的类型是 never。

交叉类型 A & B 要求同时满足 A 和 B。A7.id 是 number，B7.id 是 string，一个值不可能既是 number 又是 string，所以 id: number & string = never，整个 C7 基本不可用。

extends 不等价于 &：interface C extends A, B 若 id 冲突会直接编译报错，比 & 更早暴露问题。

三、泛型

必练

Q8 · 手写 identity 和带约束的 getProperty

实现以下两个泛型函数：

function identity<T>(value: T): T { ... }
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] { ... }
查看答案 
function identity<T>(value: T): T {
  return value;
}

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

原因：

  • identity：T 由传入参数推断，入参和返回值类型一致，比 any 安全
  • K extends keyof T：K 只能是 T 的键名，保证 obj[key] 合法；返回 T[K] 表示取 T 上 K 属性对应的类型
选练

Q9 · 下面 T 推断结果是什么？

📌 场景
function wrap<T>(value: T) {
  return { value };
}
const r1 = wrap(42);
const r2 = wrap('hi');

r1.value 和 r2.value 的类型？

查看答案
  • r1.value: number
  • r2.value: string

wrap(42) 时 T 推断为 number；wrap('hi') 时 T 推断为 string。泛型 T 由实参决定，每个调用点推断独立。

必练

Q10 · 为什么需要泛型而不是直接用 any？

查看答案

any 会关闭类型检查，失去 TS 意义。

function identityAny(x: any) { return x; }
const n = identityAny('hello');
n.foo();  // 不报错，运行时才炸

function identity<T>(x: T): T { return x; }
const s = identity('hello');
s.foo();  // ✅ 编译报错：string 上没有 foo

泛型在「保持灵活」的同时「保留具体类型信息」。

选练

Q11 · 实现泛型函数 first

first([1,2,3]) 应返回 number | undefined，怎么写？

查看答案 
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

空数组时没有第 0 个元素，所以返回 T | undefined 而不是 T。调用 first([1,2,3]) 时 T 推断为 number。

四、工具类型 Utility Types

必练

Q12 · 以下工具类型结果是什么？

📌 场景
interface User11 {
  id: number;
  name: string;
  email?: string;
}

Partial / Required / Pick / Omit / Record 的结果类型？

查看答案
  • Partial<User11> → 所有属性变可选 { id?: number; name?: string; email?: string }
  • Required<User11> → 所有属性变必填 { id: number; name: string; email: string }
  • Pick<User11, 'id' | 'name'> → { id: number; name: string }
  • Omit<User11, 'email'> → { id: number; name: string }
  • Record<'a' | 'b', number> → { a: number; b: number }

实现思路：

Partial:  { [K in keyof T]?: T[K] }
Required: { [K in keyof T]-?: T[K] }
Pick:     { [K in Keys]: T[K] }
Omit:     Pick<T, Exclude<keyof T, Keys>>
Record:   { [K in Keys]: V }
选练

Q13 · ReturnType / Parameters / Exclude / Extract

📌 场景
function q13_fn(x: number, y: string): boolean {
  return x > 0;
}

ReturnType / Parameters / Exclude / Extract 的结果？

查看答案
  • ReturnType<typeof q13_fn> → boolean
  • Parameters<typeof q13_fn> → [number, string]
  • Exclude<'a' | 'b' | 'c', 'a'> → 'b' | 'c'
  • Extract<'a' | 'b' | 'c', 'a' | 'x'> → 'a'

Exclude 从 T 中去掉能赋给 U 的类型；Extract 从 T 中保留能赋给 U 的类型。

选练

Q14 · 手写 MyPartial<T> 和 MyPick<T, K>

查看答案 
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };

这是「映射类型」语法：[K in keyof T] 遍历 T 的每个键，右边定义新类型。

选练

Q15 · 把 User11 所有属性变成 readonly 且必填，怎么写？

查看答案 
type R = Required<Readonly<User11>>;
// { readonly id: number; readonly name: string; readonly email: string }

Readonly 给每个属性加 readonly；Required 把 email? 变成 email 必填。先 Readonly 再 Required 或反过来都可以。

五、typeof / keyof / 索引访问

必练

Q16 · 下面类型分别是什么？

📌 场景
const config15 = {
  host: 'localhost',
  port: 8080,
  debug: true,
} as const;

type Q16_Host = typeof config15.host;
type Q16_Config = typeof config15;
type Q16_Keys = keyof typeof config15;
type Q16_Port = (typeof config15)['port'];
查看答案
  • typeof config15.host → 'localhost'（字面量，因为 as const）
  • typeof config15 → { readonly host: 'localhost'; readonly port: 8080; readonly debug: true }
  • keyof typeof config15 → 'host' | 'port' | 'debug'
  • (typeof config15)['port'] → 8080（字面量类型）

typeof 在类型位置表示取值的 TS 类型；keyof 取对象所有键的联合；T['port'] 叫索引访问类型。

选练

Q17 · 实现 GetValueType<T, K>

取 T[K] 的类型，怎么写？

查看答案 
type GetValueType<T, K extends keyof T> = T[K];

K extends keyof T 保证 K 一定是 T 的合法键，T[K] 是 TS 内置的索引访问语法。

六、联合类型 & 收窄

必练

Q18 · 以下函数体为何报错？如何改？

📌 场景
function q18_pad(value: string | number, padding: string | number) {
  if (typeof value === 'string' && typeof padding === 'string') {
    return value + padding;
  }
  return value + padding; // 报错原因？
}
查看答案

原因：+ 运算符要求两边都是 string 或都是 number。value 和 padding 各自是 string | number，但 TS 不会记住「它们在同一分支里被同时收窄」。最后的 return 仍可能是 string + number 或 number + string。

改法：

  • 分别处理四种组合
  • 或统一转 string：return String(value) + String(padding)
  • 或统一转 number（若业务允许）
必练

Q19 · 判别联合（Discriminated Union）

📌 场景
type Shape19 =
  | { kind: 'circle'; radius: number }
  | { kind: 'rect'; width: number; height: number };

function area19(s: Shape19): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.radius ** 2;
    case 'rect':   return s.width * s.height;
  }
}

switch (s.kind) 后，TS 如何收窄类型？

查看答案

每个成员都有相同的判别字段 kind（字面量类型不同）：

  • case 'circle' → s 有 radius
  • case 'rect' → s 有 width, height

这是 TS 做控制流收窄最常用模式之一（Tagged Union）。

选练

Q20 · user 在 if 块内外类型有何变化？

📌 场景
function q20_narrow(user: string | null) {
  if (user) {
    console.log(user.toUpperCase()); // user 此处类型？
  }
  // user 此处类型？
}
查看答案
  • if (user) 块内 → string
  • if 块外 → string | null

这叫 Control Flow Analysis（控制流分析）。if (user) 排除了 null 和 undefined（falsy），块内 TS 收窄为 string。出了 if 块，类型恢复为 string | null。

七、any / unknown / never

必练

Q21 · any 和 unknown 区别？下面哪些合法？

📌 场景
function q21_any_unknown(x: unknown) {
  x.foo();
  (x as string).toUpperCase();
  if (typeof x === 'string') x.toUpperCase();
}
查看答案
  • x.foo() → ❌ 报错
  • (x as string).toUpperCase() → ✅ 编译通过（断言跳过检查，但不安全）
  • if (typeof x === 'string') x.toUpperCase() → ✅ 合法

unknown = 不知道是什么类型，使用前必须先检查。any = 放弃检查，啥都能干（不安全）。unknown 强制你先收窄，适合接外部不可信数据。

必练

Q22 · never 出现在哪些场景？穷尽检查怎么写？

📌 场景
type Action22 = { type: 'add'; n: number } | { type: 'reset' };

function reducer22(state: number, action: Action22): number {
  switch (action.type) {
    case 'add':   return state + action.n;
    case 'reset': return 0;
    default:
      const _exhaustive: never = action;
      return _exhaustive;
  }
}
查看答案

never 的常见场景：

  1. 不可能到达的分支（穷尽检查）
  2. 总是 throw 的函数（永不返回）
  3. 空数组 as const [] 的元素类型
  4. 交叉类型冲突（如 number & string）

若 Action22 新增 { type: 'mul' } 但 switch 没处理，action 在 default 里类型不是 never，编译报错，提醒你漏了分支。

选练

Q23 · 下面函数返回类型为何推断为 never？

📌 场景
function q23_throw(): never {
  throw new Error('fail');
}
查看答案

函数体总是 throw，永远不会正常 return。never 表示「不会有任何值返回」，比 void 更准确。调用方若写 const x = q23_throw()，x 的类型是 never（unreachable）。

八、函数重载 & 可选/只读

选练

Q24 · 重载签名 vs 实现签名，调用 createDate 时返回类型？

📌 场景
function createDate(timestamp: number): Date;
function createDate(year: number, month: number, day: number): Date;
function createDate(a: number, b?: number, c?: number): Date {
  if (b !== undefined && c !== undefined) {
    return new Date(a, b - 1, c);
  }
  return new Date(a);
}

const d1 = createDate(1700000000000);
const d2 = createDate(2024, 6, 14);

d1、d2 的类型？

查看答案

d1: Date | d2: Date

调用者只看到「重载签名」，看不到实现签名。实现签名 createDate(a, b?, c?) 必须兼容所有重载，但对外隐藏。

选练

Q25 · ? 和 | undefined 是一回事吗？

interface 里 name?: string 等价于什么？

查看答案

name?: string 大致等价于 name: string | undefined（读取时），但在 strictOptionalProperties 开启时有区别：

  • name?: string → 可以「没有 name 这个键」，也可以 name: undefined
  • name: string | undefined → 键必须存在，值可以是 undefined

可选属性 ? 表示「可以省略该属性」；显式 | undefined 表示「键要有，值可为空」。

九、enum & const & 字面量

选练

Q26 · enum 和 const 对象 + union 优劣？生产更推荐哪种？

查看答案

推荐 as const + union。

enum 的问题：

  • 编译后生成额外 JS 对象（数字 enum 还有反向映射），体积更大
  • Tree-shaking 不友好
  • 数字 enum 行为不直观（自动递增）

as const + union 的优势：纯类型层面零开销，值就是普通对象易调试，现代 TS 社区主流做法。

选练

Q27 · 下面输出类型/值是什么？

📌 场景
enum Direction26 { Up, Down, Left, Right; }
console.log(Direction26.Up, Direction26[0]);
查看答案

输出：0 和 'Up'

数字 enum 默认从 0 递增，TS 还会生成反向映射 Direction26[0] === 'Up'。字符串 enum 没有反向映射；const enum 编译内联，运行时可能没有 enum 对象。

十、进阶 & 手写

选练

Q28 · 手写 DeepReadonly<T>

查看答案

一层：

type DeepReadonly<T> = { readonly [K in keyof T]: T[K] };

多层（递归）：

type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

映射类型遍历所有键，readonly 加只读。递归版对嵌套对象继续展开。

必练

Q29 · 条件类型 T extends U ? X : Y — Result 是什么？

📌 场景
type IsString29<T> = T extends string ? true : false;
type Result29A = IsString29<string>;
type Result29B = IsString29<number>;
type Result29C = IsString29<string | number>;
查看答案
  • Result29A = true
  • Result29B = false
  • Result29C = boolean

条件类型在 T 是「裸类型参数」且为联合类型时会「分发」（分布式条件类型）：

IsString29<string | number>
= IsString29<string> | IsString29<number>
= true | false
= boolean

若 T 不是裸类型参数（如 [T] extends [string]），则不会分发。

选练

Q30 · 实现 TupleToUnion<T>

[string, number] → string | number，怎么写？

查看答案 
type TupleToUnion<T extends readonly unknown[]> = T[number];

T[number] 表示用 number 索引 T 的所有元素类型。对元组 [string, number]，number 索引可能取 0 或 1 位置，所以得到 string | number。

十一、概念口述题

必练

Q31 · TS 的结构化类型（Structural Typing）是什么？

和名义类型（Nominal Typing）有何不同？

查看答案

答案：只要「形状」兼容，就认为类型兼容，不要求显式声明继承关系。

interface Point { x: number; y: number; }
const p = { x: 1, y: 2, z: 3 };
fn(p)  // 可以，多余属性 z 不影响

对比 Java/C# 名义类型：必须 implements/extends 才算那个类型。

选练

Q32 · strictNullChecks 打开前后有何变化？

查看答案
  • 关闭：null/undefined 可以赋给几乎所有类型（历史行为，易出 bug）
  • 开启：必须显式 number | null，调用前需判空

严格空值检查是 TS 减少「运行时 null 报错」最有效的选项之一。

选练

Q33 · declare / .d.ts 文件作用？什么场景需要？

查看答案

作用：只声明类型，不写实现。告诉 TS「运行时存在这个变量/模块，形状是这样」。

场景：

  • 给无类型的 JS 库写类型（@types/xxx）
  • 全局变量如 window.__APP_CONFIG__
  • 模块 shims（*.vue, *.css）
选练

Q34 · type 和 interface 在 extends 交叉类型时，同名属性冲突会怎样？

📌 场景
interface A { id: number; }
interface B { id: string; }
interface C extends A, B {}  // 会怎样？
type T = A & B;              // id 是什么？
查看答案
  • interface C extends A, B → ❌ 编译报错：Interface 'C' cannot simultaneously extend...
  • type T = A & B → id: never（不报错但类型不可用）

extends 冲突直接报错；交叉类型把冲突「压成 never」，更隐蔽。

选练

Q35 · Vue3 / React 项目里，组件 props 类型一般怎么定义？

泛型组件见过吗？

查看答案

React：

interface Props { title: string }
function Card({ title }: Props) { ... }

Vue3：

const props = defineProps<{ title: string; count?: number }>();

泛型组件：

function List<T>({ items }: { items: T[] }) { ... }

props 本质是对象，用 interface/type 描述形状；泛型组件让 items 与 render 项类型联动。

十二、运行时

选练

Q36 · 运行时输出什么？（TS 编译后 erase 类型）

📌 场景
const obj = { a: 1, b: 'x' };
console.log(typeof (obj as { a: number; b: string }).b);
console.log('types erased at runtime');
查看答案

输出 'string' 和 'types erased at runtime'

TS 类型只在编译期存在，编译成 JS 后类型注解全部擦掉。as { a: number; b: string } 只是编译期断言，不影响运行时。obj.b 运行时就是 'x'，typeof 得到 'string'。

面试常考：TS 不是运行时类型系统（除非用 zod/io-ts 等做 runtime validation）。
