Q1 · NestJS 核心：Module、Controller、Service 各做什么？

📌 场景

前端调 GET /api/projects/:id——Nest 里请求经过哪些层？

查看答案
层职责类比前端
Module组织功能边界、依赖注入容器feature 模块 / 路由模块
Controller路由、入参、HTTP 状态码页面只负责调 API 展示
Service业务逻辑、调数据库composable / store action
 
@Controller('projects')
export class ProjectController {
  constructor(private readonly projectService: ProjectService) {}
  @Get(':id')
  findOne(@Param('id') id: string) {
    return this.projectService.findOne(id)
  }
}

前端价值：知道逻辑在 Service，联调时找对人；Controller 返回结构即 API 契约。

Q2 · DTO 是什么？和前端 TS 类型怎么对齐？

📌 场景

创建选片项目接口，后端说字段用 DTO 校验——前端 TypeScript 接口怎么保持一致？

查看答案

DTO（Data Transfer Object）：定义接口入参/出参形状 + 校验规则。

export class CreateProjectDto {
  @IsString()
  name: string
  @IsEnum(ProjectStage)
  stage: ProjectStage
}

前后端对齐：

  • Monorepo 共享 shared-types 包
  • 或 OpenAPI/Swagger 生成前端 client
  • 联调前对字段名、枚举值、nullable 达成一致

Q3 · 中间件、守卫、拦截器、管道执行顺序？

📌 场景

请求要带 JWT、要校验角色、要统一包装 { code, data, message }——各放哪？

查看答案

顺序（简化）：Middleware → Guard → Interceptor(before) → Pipe → Controller → Interceptor(after) → Exception Filter

组件用途
Middleware日志、CORS、raw body
Guard鉴权、角色（CanActivate）
Pipe参数校验、类型转换（ValidationPipe）
Interceptor统一响应格式、耗时日志
Exception Filter全局 404/500 格式化

前端对应：Axios 拦截器 ≈ 客户端侧的 Guard + Interceptor，见 HTTP Q9。

Q4 · RESTful API 设计前端要关注什么？

📌 场景

列表接口分页字段叫 page/pageSize 还是 offset/limit？错误怎么返回？

查看答案
  • 资源命名：复数名词 /projects，动词用 HTTP 方法表达
  • 分页：统一 { list, total, page, pageSize }，前端封装适配层
  • 错误：HTTP 状态码 + 业务 code + message；401/403 语义清晰
  • 版本：/api/v1 或 Header 版本号
  • 幂等：POST 创建带 clientRequestId

HTTP 方法见 HTTP Q1。

Q5 · 前后端联调标准流程？你作为前端会推动什么？

📌 场景

猫咔选片状态流转 7 个状态——怎么减少接口字段反复改？

查看答案
  1. 需求评审：页面状态机 ↔ 接口状态枚举对齐
  2. Swagger/Apifox 先定契约，Mock 并行开发
  3. 共享枚举 TS 定义（ProjectStage、ErrorCode）
  4. 联调清单：正常流、边界、401、空列表、并发
  5. 变更走版本通知，避免 silent breaking change

面试答法：强调「契约先行 + 类型共享 + 状态枚举统一」，体现 BPO/猫咔联调经验。

Q6 · 依赖注入 DI 是什么？和前端有什么关系？

📌 场景

Service 里注入 Repository——为什么 Controller 不直接 new Service？

查看答案

DI：容器负责创建对象并注入依赖，便于测试替换 mock、解耦模块。

前端类比：Vue provide/inject、Pinia、adapter 模式注入 HTTP 客户端——业务不直接 new 具体实现。
