Q1 · merge 和 rebase 区别？团队里怎么选？

📌 场景

feature 分支开发完合并进 develop——用 merge 还是 rebase？各有什么坑？

查看答案
mergerebase
历史保留分叉 + merge commit线性，像一直在最新 main 上开发
冲突合并时解决一次可能多次 pick 时解决
风险历史杂乱勿 rebase 已推送公共分支

团队常见：PR 进 main 用 squash merge；本地同步 main 用 rebase origin/main；已发布 release 分支只 merge。

Q2 · 合并冲突怎么解决？<<<<<<< 是什么？

📌 场景

你和同事改了同一个 Vue 组件的同一行，pull 后冲突——标准处理步骤？

查看答案
  1. git pull 或 merge/rebase 触发冲突
  2. 打开文件，找 <<<<<<< / ======= / >>>>>>> 标记
  3. 人工保留正确代码，删除标记
  4. git add 标记已解决
  5. git commit（merge）或 git rebase --continue

工具：VS Code 三路合并、git mergetool；复杂冲突先和同事沟通意图。

Q3 · Git Flow / Trunk Based 你用过哪种？

📌 场景

Monorepo 多端并行开发，hotfix 怎么进生产？feature 分支从哪切？

查看答案

Git Flow（传统）：

  • main 生产 · develop 集成
  • feature/* 从 develop 切，合回 develop
  • release/* 发版 · hotfix/* 从 main 切合双分支

Trunk Based（敏捷）：

  • 短生命 feature 分支或直接 main + Feature Flag
  • CI 门禁，小步快跑

面试答法：说清你们实际用的 + 为什么（团队规模、发版频率）。

Q4 · cherry-pick 和 stash 分别什么时候用？

📌 场景

A. 生产 bug 修复 commit 要同步到 release 分支
B. 开发到一半要切分支修 hotfix

查看答案

cherry-pick：把指定 commit 应用到当前分支 → 场景 A。

git cherry-pick <commit-hash>

stash：暂存工作区未提交改动，切分支后再 pop → 场景 B。

git stash push -m "wip upload"
git checkout hotfix/xxx
# 修完回来
git checkout feature/xxx
git stash pop

Q5 · git reset 和 git revert 区别？误提交怎么办？

📌 场景

commit 已 push 到远程，发现引入了 bug——该 revert 还是 reset --hard？

查看答案
命令效果适用
reset --soft/mixed/hard移动 HEAD，改写历史仅本地未 push
revert新 commit 反向抵消已 push 公共分支

已 push：用 git revert <hash>，勿 force push main。

本地最后一次 commit 写错：git commit --amend 或 reset --soft HEAD~1。

Q6 · .gitignore、子模块、Code Review 注意什么？

📌 场景

新人把 node_modules 和 .env.local 提交了——怎么防？Review 看什么？

查看答案
  • .gitignore 覆盖 node_modules、dist、.env*.local
  • 已提交敏感文件：git rm --cached + 轮换密钥
  • Review：逻辑正确性、边界、类型、性能、安全（XSS/权限）
  • commit message 规范：feat/fix/refactor + 简述
  • 子模块：Monorepo 更常用 pnpm workspace 而非 git submodule
